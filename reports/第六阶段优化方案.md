# 第六阶段优化方案

更新日期：2026-10-01。

## 1. 目标和原则

当前 100 MSPS / 125 MHz FFT 版本已经完成仿真、实现、真板、GUI、SD 独立应用、SD 启动、物理冷启动和交付包复验。下一阶段不能继续在这个已验收版本上直接覆盖文件，而应把它冻结为可随时恢复的基线，在新版本中推进优化。

本阶段建议按以下优先级执行：

1. 将 125 MSPS 候选从当前已验证源码重新建立并完成真板晋升。
2. 如果 125/125 MHz 不能达到 150 us 分析延迟，再处理 FFT 域长组合路径并尝试 125/150 MHz。
3. 在保持 legacy 检测模式不变的前提下，增加可选的自适应噪声背景模式。
4. 只有在明确外部 ADC、DDR 连续输入或协议帧识别要求后，才进入接口扩展。

第六阶段的首要结果应是一个独立的新版本，而不是把多个候选的最好数字拼接到一起。每个候选必须使用自己的源码、构建 ID、bitstream、软件、真板报告和启动证据。

历史记录中的 125/125 MHz 候选曾得到约 0.152 ns setup 余量并完成离线构建/仿真，但没有完成真板、SD 和冷启动。原候选工作区已经删除，因此该结果只能作为可行性参考，不能作为新版本证据。

## 3. 版本和工作区管理

### 3.1 冻结当前版本

- 将当前目录放回真正的 Git 克隆中；下载的源码包没有 `.git` 历史，不能仅依赖该目录管理版本。
- 当前 100 MSPS 版本建立永久标签，例如 `phase5-reproduced-100m-final`。
- GitHub Release 附带最终 ZIP、ZIP SHA-256、`BOOT_udp.BIN`、XSA、bitstream 和四份关键验收报告。
- `main` 只接受修复和文档更新，不直接承载 125 MSPS 实验。
- 新建 `phase6/125m` 分支和独立工作树，例如 `D:\fft\fft_phase6_125m`。
- 每次实现使用独立输出根：`build/phase6/candidate_N`、`captures/phase6/candidate_N`、`reports/phase6/candidate_N`。
- 候选失败后保留源码提交、时序报告和否决原因，不覆盖前一候选。

### 3.2 构建身份

每次影响 RTL、约束、时钟、FFT IP、固件协议或检测参数的变更都必须产生新的构建 ID。报告必须同时记录：

- Git commit 和是否存在未提交修改。
- Vivado/Vitis 版本。
- `build_profile.json`、FFT XCI、RTL、约束和固件 SHA-256。
- bitstream、XSA、ELF、BOOT 镜像 SHA-256。
- 使用的实现策略和 directive。

禁止复用旧的 `current_board_validation.json`、SD、GUI或冷启动报告。报告只在其绑定的源码和二进制哈希完全一致时有效。

## 4. 主线 A：125/125 MHz 候选

### 4.1 建立候选

从当前 100 MSPS 已验证源码生成新配置：

- `sample_rate_hz = 125000000`
- `timestamp_clock_hz = 125000000`
- `fft_clock_hz = 125000000`
- `scan_lanes = 8`
- 升级构建 ID，硬件主版本和记录格式先保持不变。

重新生成 PS 时钟、XDC、FFT IP 配置、主机频率换算和固件元数据。不得只修改显示层的采样率常量。

### 4.2 先处理源时钟域路径

历史 125 MHz 候选的风险集中在源域，而不是资源不足。建议按以下顺序处理：

1. 保留第五阶段已经有效的 gap/length 边界预计算。
2. 对 `gap_min`、阈值和模式配置采用局部寄存器副本，避免高扇出配置网跨越整个检测器。
3. 将 CDF/阈值宽比较拆为高低字比较或平衡比较树；允许增加一个明确记录的流水拍。
4. 控制状态和数据 payload 分离复位；只对由 valid 屏蔽的数据寄存器移除同步复位，控制状态必须继续复位。
5. 对跨区域 reset/enable 使用等延迟副本，并验证复位中断测试，不能仅依赖综合器自动复制。
6. 每次只改变一个结构因素，生成 before/after 最差路径和等价仿真报告。

### 4.3 实现策略搜索

候选不应无限换 seed。建议固定最多三轮：

| 轮次 | 内容 | 晋升条件 |
|---|---|---|
| A1 | 当前 RTL + `Performance_NetDelay_high` | setup >= 0.10 ns |
| A2 | 源域比较和配置扇出优化 | setup >= 0.15 ns |
| A3 | A2 + 一个附加实现 seed/directive | 三次结果中最差 setup >= 0.10 ns |

工程最低门槛为 setup >= 0.10 ns、hold >= 0、CDC critical = 0、内部 unconstrained endpoint = 0。建议晋升门槛提高到 setup >= 0.20 ns、hold >= 0.01 ns；0.10~0.20 ns 只能作为真板试验候选，不能直接成为最终版本。

### 4.4 离线验证门槛

任何上板候选必须先通过：

- 344 个数字测长用例。
- 16 个核心用例和 524288 个逐点精确复数 FFT 输出。
- AXI、协议、SD 解析、帧长度和 qualification 测试。
- rect/hann、threshold/digital-zero 两种模式。
- 复位发生在装载、FFT、前缀扫描、结果发布和停止排空阶段的测试。
- 100 MSPS legacy 向量在物理频率重新换算后的等价性检查。
- 所有时间戳、Hz、us 字段均从构建配置推导，禁止残留 100 MHz 常量。

### 4.5 第一轮真板验证

先使用 JTAG，不写 SD：

1. 读取硬件版本、构建 ID、125 MHz 源/时间戳时钟和 125 MHz FFT 时钟。
2. 用独立 PS 计时器测量源时钟，建议允许范围 124~126 MHz；该测量仍不是外部计量校准。
3. 执行 36 项基础矩阵，要求所有输入样本守恒、无 UDP 缺包、无队列丢弃、无 underread、错误寄存器为 0。
4. 执行 10 s、60 s 和 300 s 连续回放，记录 FIFO high-water 和最大分析/发布延迟。
5. 执行接收端暂停、单包丢弃、黑洞、启动回复丢失和恢复测试。
6. 执行数字事件过载测试，必须明确报告 expected overload，不得将过载点描述成支持的无损工作点。

125/125 MHz 的预期收益主要来自 8192 点输入窗口时间由 81.92 us 降至 65.536 us，理论减少 16.384 us。实测分析延迟若约为 158~160 us 属于合理结果；最终必须以板测为准。

### 4.6 带宽验证

复用现有最宽 OFDM 测试定义，但所有频率轴按 125 MSPS 生成。晋升要求：

- 指定最宽信号的内部 99% OBW >= 115 MHz。
- 正/负频率、跨零、靠近 Nyquist 边界的 bin 映射正确。
- 不允许通过改变波形定义或统计窗口来制造带宽提升。
- 保存训练参数、输入向量和参考结果哈希。

如果原 100 MSPS 测试波形仅按采样率等比例扩展，96.997070 MHz 对应约 121.246 MHz，理论上可超过 115 MHz，但必须重新生成向量和实测证明。

## 5. 主线 B：150 us 延迟优化

125/125 MHz 真板结果若已 <= 150 us，则不启动本主线。若仍约为 158~160 us，建议保持源时钟 125 MHz，将 FFT 域提高到 150 MHz。

### 5.1 先拆除 FFT 域时序障碍

当前 `sm/div200` 64 位恢复除法链是 150 MHz 的首要障碍。优先方案是精确流水化，而不是用近似浮点或直接改测量定义：

1. 将 64 位每拍运算拆成两个或四个流水段，目标每段不超过 16 个 CARRY4 级。
2. 保持整数商、舍入和饱和结果逐位一致。
3. 在 valid/config_id/epoch 路径加入相同流水延迟。
4. 更新队列深度和最大延迟计数，但保持记录顺序与时间戳语义。
5. 增加除数为 0、最大 dividend、最大 divisor、相邻商边界和随机百万组比对。

若自研流水化除法仍不稳定，可评估 AMD Divider Generator IP，但必须锁定 IP 参数和 XCI，并用逐位参考证明完全一致。乘倒数近似只适用于容许误差的新记录格式，不适合直接替换当前精确语义。

### 5.2 时钟候选矩阵

在流水化除法通过后，只进行有界矩阵：

| 候选 | 源时钟 | FFT 时钟 | 用途 |
|---|---:|---:|---|
| B0 | 125 MHz | 125 MHz | A 线基准 |
| B1 | 125 MHz | 150 MHz | 首选低延迟版本 |
| B2 | 125 MHz | 166.667 MHz | 仅在 B1 未达标且余量允许时评估 |

B1 的最终门槛：setup >= 0.10 ns，hold >= 0，最大分析延迟 <= 150 us，最大发布延迟 <= 151 us。建议目标分别为 145 us 和 146 us，为板卡、工具 seed 和环境变化留下余量。

B2 不是默认目标。若需要大量 floorplan、资源复制或 setup 只勉强为正，应停止 B2，保留 B1。

### 5.3 延迟拆分测量

新增硬件计数器或报告字段，将总延迟拆分为：

- 窗口最后样本到 FFT 输入结束。
- FFT 输出完成。
- 频谱扫描完成。
- 测量/除法完成。
- 记录进入发布队列。

优化必须针对实际占比最大的阶段。若结果表明 FFT 域加速只降低很少延迟，就停止升频，转而优化扫描/测量状态机。

## 6. 噪声和检测鲁棒性

当前固定 robust 参数在 9 秒平稳噪声中没有虚警，但零事件的 95% 上界仍约为 0.999 次/秒；这不足以证明低虚警率。背景阶跃、上升和强干扰/DC 已出现保留的失败样例。

### 6.1 保留兼容模式

- `legacy` 和当前 `robust` 参数必须保持原行为和逐记录兼容。
- 新算法使用新模式位或 capability，不静默改变默认阈值。
- 硬件版本小版本递增，记录中保存 detector mode、阈值来源和 background estimate。

### 6.2 推荐的新模式

实现整数定点的自适应背景估计器：

1. 对短块能量计算慢速背景 `B`，使用移位实现的非对称 EMA。
2. 背景上升和下降使用不同时间常数，避免一个强突发立即抬高背景。
3. 进入 `Kon` 候选阶段后冻结或限速背景更新，事件结束并经过 holdoff 后恢复。
4. `Ton = max(Ton_min, B * alpha_on)`，`Toff = max(Toff_min, B * alpha_off)`，并保持 `Ton > Toff`。
5. 对突然的全带强干扰增加单独的 interference 状态，不将其伪装成正常突发。
6. 所有乘法使用定点系数；优先利用当前富余 DSP，避免继续消耗 BRAM。

### 6.3 数据集和量化门槛

测试集应至少包含：

- 三档平稳高斯噪声，多 seed，累计有效不重复时长不少于 3000 秒。
- 背景功率线性上升/下降、阶跃、脉冲干扰、CW/DC、带限噪声和混合干扰。
- QPSK、突发正弦、OFDM 在多个 SNR、幅度、长度和间隔下的检测。
- 跨分块事件、最大长度截断和事件紧邻配置切换。

建议门槛：平稳背景虚警 <= 1e-3 次/秒；指定目标信号的检出率不得低于当前 robust 基线；边界误差 P95 不得恶化；非平稳失败必须分类为 false event、merged event、miss 或 deliberate interference classification。

先完成纯离线状态连续仿真，再进入 RTL。32768 点循环 RAM 不能作为几千秒不重复噪声的实板证据；若要做真板长期噪声验证，需要新增流式输入或分块不重复装载协议。

## 7. 资源和架构约束

当前 BRAM 使用率 66.07%，是最紧张的资源；LUT、FF 和 DSP 仍有明显余量。建议设置：

- 最终 BRAM 使用率 <= 75%，即最多约 105 个 BRAM36 等效块。
- LUT <= 35%，FF <= 35%，DSP <= 35%。
- 新背景历史或长缓存不得直接复制完整 32768 点 RAM。
- 优先使用寄存器、SRL、DSP 和小型分布式 RAM实现局部流水与统计状态。
- 任何队列加深必须证明最坏服务率和内存上界。

如果未来加入真实 ADC/DDR 流式输入，建议把回放 RAM、采集接口和分析核解耦为 AXI-Stream 边界；现阶段没有明确接口要求，不应提前引入 DMA、DDR 环形缓冲和新时钟域。

## 8. 主机、固件和维护流程

### 8.1 主机与协议

- 所有 Hz/us 换算继续从板上身份寄存器读取，主机发现不匹配时拒绝采集。
- 为 125 MSPS 增加明确的速率显示和报告字段，不通过目录名推断。
- 连续采集报告同时保存 issued/accepted/FFT input/FFT output/records 和 UDP packet sequence。
- GUI 的频轴、OBW、延迟门槛和预设必须绑定构建采样率。

### 8.2 SD 和启动

- 每个晋升候选重新构建 `iq_sd.elf`、`iq_udp.elf`、FSBL 和两个 BOOT 镜像。
- 保留当前已验证 `BOOT.BIN` 及卡上备份文件，写入新候选前再创建新的随机备份。
- SD 应用仍需独立完成 16 项/64 窗口，并进行全量导出和数值验证。
- 写入后必须执行文件长度、CRC32、逐字节读回 SHA-256 和 SD 模式复位采集。
- 最终必须由用户物理断电再上电，网络首读 epoch=0，且整个冷启动验证不使用 JTAG。

### 8.3 验收工具

本次复现已将 SD 完成检测改为从当前 ELF 反汇编中提取 `main` 最终 `usleep` 调用地址。下一阶段应补充工具自测：

- 断言 `main` 中恰好存在一个最终完成调用。
- 计划记录完成地址和 `iq_sd.elf` SHA-256。
- ELF 变化后旧计划必须拒绝运行。
- XSDB 停止 PC 必须等于计划地址，否则不能宣称 SD 应用完成。

## 9. 完整晋升门槛

一个第六阶段候选只有全部满足以下条件才可替换当前 100 MSPS 默认版本：

1. 完整仿真和逐点 FFT 精确比对通过。
2. setup/hold、CDC、DRC、methodology、bus skew 和 unconstrained 检查通过。
3. 36 项基础真板测试通过。
4. 扩展压力、故障注入、GUI 和帧长度测试通过。
5. 2020 组最终矩阵和 192 项兼容检查通过；如测试定义增加，应只增不减。
6. 10/60/300 秒连续测试无丢包、无队列丢弃、无 underread、无硬件错误。
7. 125 MSPS 独立时钟测量通过。
8. 99% OBW >= 115 MHz。
9. 若宣称低延迟版本，最大分析延迟 <= 150 us。
10. SD 16 项、镜像读回、SD 复位启动和物理冷启动全部通过。
11. 最终交付 ZIP 清单逐文件复验通过。
12. 当前 100 MSPS Release 仍可下载并按原 SHA-256 恢复。

## 10. 停止和回退条件

出现以下任一情况时停止候选并回退到最近通过版本：

- setup < 0.10 ns 或任何 hold violation。
- 为满足时序而改变测量定义、FFT 数值或时间戳语义。
- 基础板测出现输入拒绝、FIFO underread、结果队列丢弃或错误位。
- 125 MSPS 带宽未达到 115 MHz，且只能通过改变测试波形定义达到。
- 150 MHz FFT 需要超过三轮实现或使 BRAM 超过 75%。
- 自适应检测提高总体得分但显著降低指定目标信号检出率。
- SD 写入读回不一致；此时禁止复位，保留临时文件和旧 BOOT 备份用于恢复。

## 11. 推荐执行顺序

1. 冻结并发布当前 100 MSPS Git 标签和 Release。
2. 从当前源码创建独立 `phase6/125m` 工作树。
3. 生成 125/125 MHz 配置和新构建 ID。
4. 完成源域路径优化、完整仿真和三轮以内的实现搜索。
5. 达到时序门槛后执行 JTAG 基础真板和独立时钟验证。
6. 完成 125 MSPS 带宽、连续运行、扩展和 GUI 测试。
7. 判断延迟是否 <= 150 us；达标则跳过 B 线。
8. 未达标时精确流水化 FFT 域除法器，构建 125/150 MHz 候选。
9. 对最终候选运行完整矩阵、SD 和物理冷启动。
10. 生成独立的新 Git 标签、GitHub Release 和经过清单复验的交付 ZIP。
11. 主线完成后再从该稳定版本建立自适应噪声检测分支。

## 12. 建议的最终交付指标

第六阶段理想目标为：125 MSPS 输入、150 MHz FFT、8 路扫描、setup >= 0.20 ns、hold >= 0.01 ns、分析延迟 <= 145 us、发布延迟 <= 146 us、内部 99% OBW >= 115 MHz、正常支持范围内零丢样/零丢记录、BRAM <= 75%，并完整通过 SD 和物理冷启动。

最低可接受成果为：125/125 MHz、setup >= 0.10 ns、分析延迟较当前至少降低 15 us、OBW >= 115 MHz，其他数值语义和完整验收不退化。如果最低门槛仍无法稳定满足，应保留当前 100 MSPS 版本为正式版本，并将 125 MSPS 标记为实验候选。
