# 第四阶段时钟可行性结论

正式候选维持 100 MSPS 输入和 125 MHz FFT。125/125 MHz 实验完成布局布线，setup 为 0.029 ns、hold 为 0.051 ns，CDC 严重问题为 0；它通过非负时序检查，但未达到本轮 0.10 ns 的工程晋升门槛，未部署到板卡。

## 实际时钟

以下数据来自应用板卡 PS7 预设后执行 `validate_bd_design` 的结果，并同时读取 FCLK 引脚频率。请求值不能直接当作实际频率。

| 源 / FFT 请求 MHz | 实际源 / FFT MHz | 结论 |
|---|---|---|
| 100 / 125 | 100 / 125 | 保留正式配置 |
| 102 / 125 | 100 / 125 | 没有实际提频 |
| 103 / 125 | 100 / 125 | 没有实际提频 |
| 104 / 125 | 100 / 125 | 没有实际提频 |
| 125 / 125 | 125 / 125 | 完成物理时序实验，裕量不足 |
| 125 / 150 | 125 / 142.857132 | 与声明 150 MHz 的接口属性冲突，BD 拒绝 |
| 125 / 156.25 | 125 / 150 | 合法生成组合，未完成物理实现和板测 |

第一次请求 125/150 的失败日志保留。156.25 的请求能生成 150，不意味着直接请求 150 也能生成同一频率；最终采用验证后的实际参数与引脚读数。[原始时钟矩阵](../build/phase4_clock_matrix_20260922_v4/clock_matrix.csv)可复核。

## 未晋升原因

125/125 MHz 的最差路径位于源域，从 `gap_min` 寄存器到数字零检测器 `burst_data` 的时钟使能。数据路径为 7.591 ns、11 级逻辑，布线占 62.523%。提高 FFT 时钟本身不会消除这条源域路径。下一次若单独立项提高输入速率，需要围绕检测确认逻辑与结果写使能重新安排流水，并验证包络边界语义。

该实验仍保留 100 MSPS 的旧测量元数据，明确禁止作为可部署镜像；没有执行软件构建、SD 更新或 125 MSPS 真板吞吐验收。当前只声明完成时钟可行性研究，不声明项目输入已达到 125 MSPS。

102–104 MHz 请求没有形成新的实际时钟；125 MHz 又没有达到已定裕量门槛，因此结束本轮提频分支。保留已验收的 100 MSPS 路线，继续完成八路扫描和构建身份组合的全套验收。[候选决策和冻结证据](phase4_candidate_decisions.json)记录各版本边界。
