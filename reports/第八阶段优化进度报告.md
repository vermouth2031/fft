# 第八阶段优化进度报告

日期：2026-10-03  
分支：`phase8/ddr-dma-streaming`  
板卡：Zybo Z7-20，目标 IP `192.168.1.10`  
构建身份：`bae26b27515a813bbef3093a68992465`

本轮修复了两个会阻止真实交互的启动问题。lwIP 的 Zybo GEM0 初始化现在固定使用 RTL8211E 的 PHY 地址 1，PHY 复位轮询有上限，自动协商暂未给出 10/100/1000 Mbps 时使用 1000 Mbps 的有效 MAC 速度。SDT lwIP 模板不再在 `init_platform()` 中调用 `init_timer()`；固件由 Zynq 全局定时器轮询 `timer_callback()`，保持 50 ms 的 lwIP 节拍，避免 Vitis 2026.1 的 interval timer 在中断控制器准备前触发。

已完成并通过：

- Vitis BSP、UDP 固件、SD 固件和 FSBL 构建。
- `BOOT_sd.BIN`、`BOOT_udp.BIN`、`BOOT.BIN` Bootgen 生成及 SHA-256 绑定。
- 发布目录重新打包，`scripts/package_release.py --check` 通过。
- 主机协议、检测器、帧长参考、SD 解析、软件对应性回归通过。
- SD 维护写入器 `prepare` / `build` 通过，未修改物理 SD 卡。
- JTAG 装载后 ARM0 位于正常主循环，板端 IP 为 `192.168.1.10`，PHY 地址为 1，未再出现 PHY 或 GIC 断言。

当前不能宣称的项目：

- Phase 8 UDP/DMA 交换、切换压力和 60 秒稳定性。
- 当前镜像写入 SD 卡、读回校验和 SD 启动。
- 本版本的物理断电冷启动。

阻塞证据：运行 `ipconfig` 时电脑所有有线适配器均为 `Media disconnected`，仅无线网卡拥有 `10.8.218.227/16`；电脑没有 `192.168.1.20/24` 的有线接口，因此 UDP 验收脚本无法向板卡发送命令。恢复网线和电脑静态地址后，应先运行：

```powershell
python scripts/deploy_board.py --out reports/deploy_phase8_20261003_timerfix_linkrestored.json
python scripts/phase8_dma_validation.py --out reports/phase8_dma_20261003
```

随后才能执行 `scripts/maintenance/sd_boot_update.py write --write --reboot`，再进行物理断电冷启动。旧 Phase 7 验收报告不作为本版本的替代证据。
