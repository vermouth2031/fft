# 板卡演示操作卡

本卡说明当前源码的操作方法；是否已完成新版构建、实板和实体 SD 启动验证，请先查看 [验收状态](验收状态.md)。演示输入为电脑装载后的板内 I/Q 回放，固定 100 MSPS、I/Q 各 16 bit、8192 点 FFT，不使用外部 ADC。

## 1. 准备与版本

- USB JTAG/UART、网线和板卡电源连接就绪。
- 板卡默认地址为 `192.168.1.10/24`；直连电脑网卡可设 `192.168.1.20/24`，不填默认网关。
- UART 设置为 115200、8N1。完整测量记录通过网线传输。
- 同时只运行一个采集端。GUI、CLI 和自动验收脚本不能并行采集。

以下命令在工程目录执行。首次构建或修改源码后先运行完整构建，再部署当前产物：

```powershell
Set-Location D:\fft\iq_analyzer
.\scripts\run.ps1 -Action All
python .\scripts\deploy_board.py --board 192.168.1.10
```

部署入口检查硬件版本、数字零能力和停止状态，并记录产物散列。新版数字零功能要求 VERSION 至少为 `0x00010001`，且 `CAPABILITIES` bit0 为 1；旧 BOOT 会明确报不支持。JTAG 装载仅改变本次运行内容，**不更新 SD 卡，断电重启可能回到卡上的旧版本**。

## 2. 先演示一次完整波形

1. 运行 `python .\host\monitor.py`；本机也可使用根目录 `Open_IQ_Monitor.cmd`。
2. 保持板卡 IP 为 `192.168.1.10`，窗选择 `hann`。
3. 选择 `data/vectors/burst_fs4.bin`。
4. 检测模式选择 `digital-zero`，零间隔确认点数填 `32`，取消“循环回放”。
5. 点击“开始采集”，等待工作线程保存完成、按钮恢复可用。
6. 预期显示“数字零背景波形长度” **24,576 对 I/Q / 245.76 µs**，起点2048、终点26624。这是应核对的参考值，不是预先认定的本次实测结果。
7. 查看“采集完整性”和“数值参考核验”。单次数字零采集自动核对长度、边界标志、能量、峰值及 RMS；FFT 的逐项核对由自动验收入口另行完成。

保持同一向量，将检测模式切为 `threshold` 再采集。默认门限检测的参考长度为 **24,591 点**，多出的 15 点来自 16 点滑动能量和的尾部。此时界面应显示“门限突发长度”，普通采集中的数值参考状态为“未执行”，不能把它说成已经完成独立数值比对。

`gap_min` 只控制数字零模式：连续这么多对 `I=Q=0` 才确认波形结束；短于它的内部零段计入同一波形。它的范围为 1–65535，默认32，不替代 threshold 的 Kon/Koff。

## 3. 连续频谱与主动停止

1. 选择 `data/vectors/qpsk_sps4.bin`，设置持续时间10秒，Hann窗，选择所需检测模式。
2. 勾选“循环回放”，点击“开始采集”。输入参考包络来自文件；频谱、幅度、频率和99%带宽来自 FPGA。
3. 可等待定时结束，也可点击“窗口边界停止”。停止按钮保留完整 FFT 窗口，但最后一段波形可能尚未结束。
4. 换成 `qpsk_sps2.bin`，比较频谱与带宽；QPSK 的最大谱线不等于载波中心，应同时看带宽中心。
5. 用 `tone_pos_fs4.bin`、`tone_neg_fs4.bin` 的单次回放演示 ±25 MHz 单音。
6. “打开已有记录”可离线查看采集目录。原始记录、JSON、CSV和元数据保存在 `captures/`。

循环回放重复同一段装载文件，不能称为电脑通过千兆网口实时输入100 MSPS新数据。GUI更新频率也不等于输入采样率。

## 4. 怎样判断记录可用

- `capture_complete=true` 表示本轮采集完整性检查通过，仍需区分是否做过独立数值核验。
- `START_UNCONFIRMED`（bit13）表示前导零不足或强制分段续段，起点未确认。
- `CAPTURE_TRUNCATED`（bit8）表示停止前未确认波形结束。
- `DETECTOR_TIMEOUT`（bit10）表示达到最大允许长度后的观测分段。
- `DIGITAL_ZERO`（bit12）说明这条64字节burst记录使用数字零背景定义。
- 起点未确认、截断或上限分段不能当作完整波形帧长；本工程不识别通信协议帧头。
- `capture_complete=false` 时保留数据诊断，网络恢复后重新采集；软件不会补造丢失记录。

采样率与版本记录在 `capture.json`；延迟按记录中的采样率换算，要求不超过2 ms。2026-09-17基线的最大分析199.78 µs、最大发布200.12 µs仅是历史证据，本轮应读取新验收报告。

## 5. 命令行和自动验收

单次数字零采集及独立测量核对：

```powershell
python .\host\iq_client.py capture --board 192.168.1.10 `
  --vector .\data\vectors\burst_fs4.bin --window hann `
  --detector digital-zero --gap-min 32 --out .\captures\demo_digital_zero
python .\scripts\verify_board_capture.py .\captures\demo_digital_zero
```

输出目录请每轮使用新名字。省略 `--detector` 时为 threshold；CLI增加 `--cyclic --seconds 10` 可循环运行10秒。

完成当前构建和上面的部署后，可运行统一验收入口：

```powershell
.\scripts\run_network_validation.ps1 -Board 192.168.1.10 -Suite smoke
.\scripts\run_network_validation.ps1 -Board 192.168.1.10 -Suite full
```

- smoke：两种向量、Hann窗、两种检测模式，共4组有限采集。
- full：8种向量×2种窗×2种模式，共32组有限采集；每种模式另做10秒及60秒连续采集，共4组连续采集。
- 每轮创建新的 `captures/acceptance_时间戳`，保存每例测量核验及总 `board_validation.json`；完整full通过才更新 `reports/current_board_validation.json`。
- `Run_Network_Tests.cmd` 使用默认full流程。脚本不改变网卡配置，也不再依赖原电脑网卡GUID；可传 `-Python 'Python完整路径'`。
- 该入口要求匹配的 `reports/current_deployment.json` 和构建产物散列，不能直接沿用旧部署报告。

可单独运行GUI验收，输出目录必须不存在：

```powershell
python .\scripts\check_monitor_board.py --board 192.168.1.10 `
  --out .\captures\gui_demo_new
```

它会实际打开界面，测试定时采集、数字零单次、主动停止和离线查看，保存截图与报告；可加 `--offline-capture '已有采集目录'` 测试历史数据。运行期间不要另外发起采集。

## 6. 一张 SD 卡切换启动模式

先关闭开发板电源，将卡插回电脑，再把**当前已构建并核对散列**的选定 BOOT.BIN 放在卡根目录，安全弹出后插回板卡。

| 用途 | 启动文件 | 说明 |
|---|---|---|
| 自动16组门限测试 | `release/sd_card/BOOT.BIN` | 同时需要 `VECTORS/`；SD程序仍是threshold模式 |
| 网络交互与两种检测模式 | `release/ethernet_sd_card/BOOT.BIN` | 等待电脑发起采集；数字零功能还需匹配新版硬件与固件 |

一次只放一个根目录 BOOT.BIN。网络验收成功不代表实体SD已替换；重新上电后的版本和测试结果必须单独核对。更完整的寄存器、flags与兼容协议见 [使用与设计说明](使用与设计说明.md)。

2026-09-19当前板卡已安装新版网络BOOT并通过SD模式系统复位数值测试，可直接开始网络采集。交付包中的预编译启动文件位于`boot_packages/sd_card/`和`boot_packages/ethernet_sd_card/`，本地构建输出仍位于`release/`。

后续如需在卡仍插在开发板时维护，可使用[JTAG维护操作说明](../scripts/maintenance/操作说明.md)中的只读SD测试导出与校验更新工具。实际写入入口有明确的`--write`参数，并保存原BOOT；普通采集无需运行维护工具。
