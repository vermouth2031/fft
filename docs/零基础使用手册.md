## 1. 这个项目到底在做什么

### 1.1 把它想成一台“数字信号检查仪”

电脑中有一串表示信号的数据。把它交给开发板，开发板回答：

- 信号有多强？
- 信号从什么时候开始，到什么时候结束，持续多久？
- 信号的频谱中，哪个频率最强？
- 信号的主要功率占用了多宽的频率范围？

这四个问题，对应上位机顶部的四张卡片：

| 上位机名称 | 初学者理解 |
| --- | --- |
| 信号幅度 | 信号整体有多强，同时还能查看瞬间最强值 |
| 帧长度 | 检测到的一段活动波形持续了多久 |
| 频点 | 当前分析窗口里，功率最大的频率位置 |
| 带宽 | 当前分析窗口里，主要功率分布的频率范围有多宽 |

### 1.2 你现在的输入是“数字 IQ 文件”

当前项目的常用输入，是电脑中保存好的 IQ 二进制文件。

你可以把文件想成一段已经写好的乐谱。开发板按照规定速度不断读取这段乐谱，再分析它。

当前系统还没有把天线收到的模拟无线电信号直接接进来，也没有集成外部 ADC 采集前端。因此，“开始采集”在这个项目中主要表示：

> 装载数字 IQ，启动板内回放和硬件分析，再把测量记录收集到电脑。

它不是“打开天线开始接收空气中的全部无线信号”。

### 1.3 分析信号，不等于读懂信号中的通信内容

例如，一段 QPSK 数据可以拿来测幅度、持续时间、频谱和占用带宽。

但是，当前系统不会因此自动告诉你：

- 它属于哪个通信协议。
- 包里写了什么文字。
- 协议帧头和校验字段在哪里。
- 发送方的身份是什么。

这些属于调制识别、解调、同步或协议解析，是另外一类工作。

## 2. 从零认识 IQ、采样点、时间和单位

### 2.1 什么叫“信号”

先把信号理解成“随着时间变化的一串数”。

例如：

~~~
时间先后：  第 0 点   第 1 点   第 2 点   第 3 点
某个数值：      0        3        5        2
~~~

模拟信号通常用连续变化的物理量表示，例如随时间变化的电压。把它按一定时间间隔取样，再把每次取到的数值用有限位数编码，就得到可保存、可计算的数字样本。

你的项目处理的是数字信号。

### 2.2 为什么一个时间点要用 I、Q 两个数

你的信号在每一个时间点，用两个数共同表示：

- I：同相分量。
- Q：正交分量。

暂时不用记住专业名字。可以把它们看成平面上一个箭头的横坐标和纵坐标。

例如 I=3、Q=4，就表示箭头指向点 (3,4)。箭头的长度是：

~~~
幅度 = √(I² + Q²) = √(3² + 4²) = 5
~~~

I、Q 的组合同时保留了信号的强弱和相位变化信息。相位可以粗略理解为“箭头当前朝哪个方向”。

专业写法是：

~~~
x[n] = I[n] + jQ[n]
~~~

其中 n 是第几个采样点，j 表示把 Q 放在与 I 垂直的方向上。初学时，把 x[n] 理解成“第 n 个时刻的一对 IQ”就足够了。

### 2.3 一对 IQ 才是本项目说的“一个采样点”

在本项目中：

~~~
第 0 个采样点：I0、Q0
第 1 个采样点：I1、Q1
第 2 个采样点：I2、Q2
~~~

每个采样点有两个分量，不是把 I 算一个点、Q 再算另一个点。

所以：

> 160 MSPS = 每秒处理 1.6 亿对 IQ。

### 2.4 I16/Q16 是什么意思

- I16：I 用一个 16 bit 的有符号整数表示。
- Q16：Q 用另一个 16 bit 的有符号整数表示。
- 一个分量占 2 字节，一对 IQ 占 4 字节。

16 bit 有符号整数的范围是：

~~~
−32768 ～ +32767
~~~

负数是正常的信号分量，不等于出错。

特别注意：I 或 Q 为负，不代表“信号幅度为负”。幅度由平方和开根号得到，始终不小于零。

文件的格式是：

~~~
I0, Q0, I1, Q1, I2, Q2, ...
~~~

每个数按“小端”方式保存。初学者只需要知道：必须使用配套格式的 IQ 文件，不能随意把 MP3、普通文本或其他二进制文件改名为 .bin。

### 2.5 采样率是什么意思

采样率回答：

> 每秒按顺序使用多少个采样点？

本项目最终配置为：

~~~
Fs = 160000000 对 IQ/秒 = 160 MSPS
~~~

因此，一个采样点对应的时间间隔是：

~~~
1 ÷ 160000000 秒 = 6.25 ns
~~~

它与“这个信号本身是 20 MHz 还是 40 MHz”不是同一个概念：

- 采样率：你观察、提供数据的节拍。
- 信号频率：被观察的信号变化、旋转的快慢。

可以类比拍视频：相机每秒拍多少帧，与画面里的风扇每秒转多少圈，是两个问题。

### 2.6 常见单位速查

| 单位 | 意思 | 换算 |
| --- | --- | --- |
| bit | 二进制的一位 | 只能表示 0 或 1 |
| Byte、B | 字节 | 1 B = 8 bit |
| Hz | 每秒多少个周期 | 1 Hz = 每秒 1 次 |
| kHz | 千赫兹 | 1 kHz = 1000 Hz |
| MHz | 兆赫兹 | 1 MHz = 1000000 Hz |
| MSPS | 每秒百万个采样点 | 本项目的一个点是一对 IQ |
| s | 秒 | 基本时间单位 |
| ms | 毫秒 | 1 ms = 0.001 s |
| μs、µs、us | 微秒的不同写法 | 1 μs = 0.001 ms |
| ns | 纳秒 | 1 ns = 0.001 μs |

本项目最常用的换算是：

~~~
持续时间 / μs = IQ 点数 ÷ 160
~~~

| IQ 点数 | 在 160 MSPS 下的时间 |
| ---: | ---: |
| 1 | 0.00625 μs，即 6.25 ns |
| 16 | 0.100 μs |
| 32 | 0.200 μs |
| 512 | 3.200 μs |
| 1024 | 6.400 μs |
| 8192 | 51.200 μs |
| 16384 | 102.400 μs |
| 32768 | 204.800 μs |

### 2.7 三种“长度”一定要分开

| 名称 | 是什么 | 当前例子 |
| --- | --- | --- |
| 文件或数据块长度 | 一个文件里有多少对 IQ | 常用 32768 对 |
| FFT 窗口长度 | 每次频谱分析拿多少对 IQ | 固定 16384 对 |
| 突发或活动包络长度 | 检测器判定的一段活动波形持续多少对 IQ | 可以是 512、8192 或其他长度 |

32768 点文件可以包含两个 FFT 窗口，却只有一段跨越窗口的突发。

因此：

> 一个文件不一定是一帧；一个 FFT 窗口也不一定是一帧。

## 3. 要测量的四项内容，分别是什么意思

### 3.1 信号幅度：有多强

#### 3.1.1 单个 IQ 点的幅度

~~~
单点功率量 p[n] = I[n]² + Q[n]²
单点幅度 A[n] = √p[n]
~~~

这里的“功率量”是根据数字码值平方得到的计算量，尚未标定为真实的瓦特。

#### 3.1.2 峰值

峰值回答：

> 在这一段数据中，最强的那个瞬间有多强？

例如某段数据的幅度依次为：

~~~
0、0、10、10、0
~~~

峰值就是 10。

#### 3.1.3 RMS

RMS 是“均方根”，用来表示整段数据的平均强弱。

计算顺序是：

1. 对每个点的 I、Q 平方后相加。
2. 对整段数据求平均。
3. 对平均值开平方。

~~~
RMS = √[(所有点的 I²+Q² 之和) ÷ 点数]
~~~

它不是直接把 I 和 Q 求普通平均。正负信号可能互相抵消，但信号并没有因此消失，所以要先平方。

#### 3.1.4 为什么上位机 RMS 可能小于包络顶上的幅度

假设一个 FFT 窗口中：

- 四分之一的点有信号，幅度为 8192。
- 四分之三的点是零。

那么：

~~~
窗口 RMS = 8192 × √(1/4) = 4096
窗口峰值 = 8192
~~~

这不是测错了，而是 RMS 把整个窗口中的零背景也算进了平均。

这个项目中还有“突发区间 RMS”：它只统计检测出来的那段活动区间。因此，窗口 RMS 和突发 RMS 可能不同。

顶部“信号幅度”卡片显示的是最新 FFT 窗口对应的 RMS；“数据与校验”中还能看到最近突发的 RMS 和峰值。

对于恒包络复单音 I=Acosθ、Q=Asinθ，I²+Q²=A²，所以复包络 RMS 约等于 A。不要直接套用只有一条实数正弦时常见的 A/√2 公式。

#### 3.1.5 “数字码值”是什么意思

上位机显示 8192，意思是数字幅度为 8192 码。

它不是：

- 8192 V。
- 8192 W。
- 8192 dBm。

当前没有外部模拟采集前端的电压、阻抗和增益标定，不能直接转换成这些物理量。

16 bit 的范围限制分别针对 I、Q 两个分量。复包络幅度可以大于 32767，例如 I=30000、Q=30000 时，幅度约为 42426.4，这与两个分量各自合法并不矛盾。

### 3.2 帧长度：这里指活动包络持续多久

在本项目里，界面中的“帧长度”实际是：

> 一段被检测器认为处于活动状态的波形，从起点到终点的持续时间。

也称“突发长度”或“活动包络长度”。

#### 3.2.1 一个最直观的例子

~~~
背景：     000000
活动：           ██████████
背景：                     000000

          开始              结束
~~~

检测器的工作，就是找出“开始”和“结束”。

两种检测模式的找法不同：

| 模式 | 怎么判断活动与背景 |
| --- | --- |
| digital-zero | I、Q 同时严格为零，才算零背景 |
| threshold | 结合最近 16 点的功率总和，与门限比较 |

#### 3.2.2 起止区间为什么写成 [开始,结束)

例如：

~~~
[16128, 16640)
~~~

意思是包含第 16128 点，一直包含到第 16639 点；第 16640 点不计入。

因此：

~~~
长度 = 16640 − 16128 = 512 点
时间 = 512 ÷ 160 = 3.2 μs
~~~

这种“左边包含、右边不包含”的表示方式，可以避免点数计算时多一或少一。

#### 3.2.3 可以跨 FFT 窗口

FFT 窗口边界在第 16384 点。

上例从 16128 到 16640，正好跨过这个边界。但是长度检测按连续样本运行，所以仍然可以给出一条 512 点突发，而不是拆成两条。

#### 3.2.4 采集结束不一定等于波形结束

如果你在信号仍然活动时停止：

~~~
原本的信号：  █████████████████……
采集结束：              |
~~~

系统只能知道“看到这里为止”。这类结果会带停止截断标志，不能当成已确认结束的完整突发长度。

### 3.3 频点：最强的频率在哪里

#### 3.3.1 时域与频域

- 时域：沿时间看波形什么时候出现、强弱如何变化。
- 频域：看信号的功率分布在哪些频率上。

可以类比一段音乐：

- 时域像看音量随时间变化。
- 频域像看低音、中音、高音各占多少。

FFT 是把一段时域数据转换成频率分布的快速算法。

#### 3.3.2 本项目的“频点”是谱峰频率

系统在分析范围内找到功率最大的 FFT 频点，将它换算成 Hz 或 MHz。

例子：

- −30 MHz 的单音比较强。
- +20 MHz 的单音比较弱。

那么顶部“频点”会显示 −30 MHz；频谱图上仍然可以看见两个峰。

它只告诉你“最高峰在哪里”，不会自动把两个频率都列成两个顶部卡片。

#### 3.3.3 负频率不是负的振动次数

对于 IQ 这种复数表示，正、负频率可理解为相对于基带中心的两个方向。

例如：

- +20 MHz：在基带中心的一侧。
- −30 MHz：在另一侧。

从旋转箭头的角度看，两者对应相反的旋转方向。

当前系统显示的是数字基带频率，没有设置一个真实射频接收机的中心频率。不要直接把 −30 MHz 当成“现实世界发射机的绝对载频”。

#### 3.3.4 谱峰、带宽中心、载频是三个概念

| 名称 | 当前含义 |
| --- | --- |
| 谱峰频率 | 哪个 FFT bin 的功率最大 |
| 带宽中心 | 99% 占用带宽两端频率的中点 |
| 调制载频或射频中心 | 由信号产生、调制或射频系统定义，当前程序不自动识别 |

对于宽带 OFDM，某个子载波最高，因此谱峰可能离带宽中心很远。这并不一定是错误。

### 3.4 带宽：主要功率占了多宽的频率范围

#### 3.4.1 先理解“频率位置”和“频率宽度”

假设一段信号主要分布在 −20 MHz 到 +20 MHz：

~~~
下边界 = −20 MHz
上边界 = +20 MHz
带宽 = 20 − (−20) = 40 MHz
中心 = [20 + (−20)] ÷ 2 = 0 MHz
~~~

把同一信号整体平移到 +25 MHz 附近，它可能分布在 +5 MHz 到 +45 MHz：

~~~
带宽仍是 40 MHz
中心变为 +25 MHz
~~~

所以：中心位置改变，不等于带宽一定改变。

#### 3.4.2 本项目使用 99% 等尾占用带宽

系统按频率从低到高，把每个频点的功率逐渐累加。

大致排除：

- 低频端 0.5% 的功率。
- 高频端 0.5% 的功率。

保留中间约 99% 功率的频率区间，再计算区间两端的频率差。

~~~
低频方向                                         高频方向
  约 0.5%  |------------- 中间约 99% -------------|  约 0.5%
           下边界                              上边界
~~~

“等尾”指两端排除的目标功率比例相同，不是左右两端都切掉相同的 MHz。

由于功率集中在一个个离散 bin 上，最终区间的功率占比不一定恰好等于 99.000000%。

#### 3.4.3 为什么单音也可能显示非零带宽

理想无限长单音非常窄，但实际只观察有限个点，还要经过窗函数和离散 FFT。

例如当前 16384 点、160 MSPS 配置下：

- 合适的相干单音加矩形窗，可能只落在一个 bin，测得 99% 带宽为 0。
- 同一个单音加 Hann 窗，功率会分布到邻近 bin，可能测得约 0.019531 MHz。

0.019531 MHz 就是约 19.531 kHz，不是 19.531 MHz。

“带宽为 0”也不表示系统能够证明真实信号具有无限精细的零宽度；它通常表示两条边界落在同一个离散 bin。

#### 3.4.4 宽带、窄带是相对描述

在当前数字频率范围内：

- 单音属于很窄的输入。
- 约 40 MHz OFDM 比较窄。
- 约 140 MHz OFDM 更宽。
- 满带测试信号接近整个 160 MHz 数字频谱跨度。

生成信号时定义的“子载波覆盖范围”，与实测 99% 占用带宽不必完全相等，因为后者依赖实际功率分布、窗函数和离散边界。

## 4. 五个赛题指标，分别是什么意思

前面的四项测量，是在描述“被测信号是什么样”。这里的五项指标，是在评价“分析系统具有什么能力”。FFT 点数、输入位宽等不是另外几种要从信号中测出的属性。

### 4.1 先把五项要求放在一起

| 序号 | 赛题指标 | 赛题要求 | 当前实现或已测结果 |
| ---: | --- | --- | --- |
| 1 | 数字基带 IQ 信号位宽 | 每路至少 12 bit | I、Q 各 16 bit |
| 2 | IQ 信号数据速率 | 至少 100 MSPS | 板内 160 MSPS |
| 3 | FFT 点数 | 至少 8192 点 | 16384 点 |
| 4 | 分析处理时间 | 不超过 2 ms | 最大 PL 分析 219.775 μs |
| 5 | 数字 IQ 信号带宽 | 单位 MHz，其他要求满足时越高越好 | 宽带矩阵主组满带子集的 99% 带宽为 158.154297～158.593750 MHz |

第 5 项题面没有给出一个固定的 MHz 最低门槛，不能自行写成“必须大于 100 MHz”之类的要求。

### 4.2 指标一：IQ 位宽 ≥12 bit

位宽回答：

> 每个 I 或 Q 数值，用多少个二进制位来表示？

12 bit 一共有 4096 种编码；16 bit 一共有 65536 种编码。

在相同归一化满量程范围下，更多位数可以表达更细的量化等级。但实际测量精度还取决于输入、噪声、定点运算和标定，不能只凭 16 bit 宣称所有结果都具有 16 bit 的实际精度。

本项目的 I 和 Q 分别都是 16 bit。它不是“I、Q 合起来只有 16 bit”。

### 4.3 指标二：IQ 数据速率 ≥100 MSPS

它回答：

> 每秒能处理多少对 IQ？

当前板内每个 160 MHz 时钟周期处理一对 IQ，因此是 160 MSPS。

与最低 100 MSPS 相比：

~~~
(160 − 100) ÷ 100 = 60%
~~~

因此可说板内处理速率比赛题最低要求高 60%。

但每对 IQ 是 4 字节，所以如果全部都是全新的原始数据：

~~~
160000000 × 4 = 640000000 字节/秒
即 640 MB/s = 5.12 Gbit/s
~~~

千兆网口不能持续供应这么多全新 IQ。因此项目先装载到存储，再由 PL 按 160 MSPS 回放。

“网口上传”“板内回放”“电脑界面刷新”是三种不同的速度。

### 4.4 指标三：FFT 点数 ≥8192

它回答：

> 每次计算频谱时，使用多少个连续 IQ 点？

当前使用 16384 点，是最低 8192 点的两倍。

在采样率固定时，FFT 点数更多：

- 一次观察的时间更长。
- 频率网格间隔更小。
- 存储和处理开销通常也更大。

当前：

~~~
窗口时间 = 16384 ÷ 160000000 = 102.4 μs
频率网格间隔 = 160000000 ÷ 16384 = 9765.625 Hz
             = 9.765625 kHz
~~~

把 FFT 的每一个频率格子称为 bin。

更细的频率格子通常有利于频率区分，但真正能不能分开两个相邻信号，还与窗函数主瓣、信噪比和两者强弱差有关。不要把 bin 间隔直接当成所有条件下的最终测量精度。

### 4.5 指标四：分析处理时间 ≤2 ms

它回答：

> 电路接收并处理一个分析窗口，从窗口首样本对应时间，到生成该窗口频域信息，需要多久？

赛题上限：

~~~
2 ms = 2000 μs
~~~

当前最大 PL 分析延迟：

~~~
219.775 μs = 0.219775 ms
~~~

约占 2 ms 上限的 11%。

另外，完整记录写入结果环形缓冲、对软件可读的最大发布延迟为：

~~~
219.993750 μs
~~~

这两个量接近，但含义不同。

点击“开始采集”后还要连接、上传文件、读回校验、配置，再启动分析；结果还要通过网络传回并刷新界面。因此：

> 从鼠标点击到看到数字的时间，不是赛题中的 PL 分析延迟。

分析延迟大于 102.4 μs 的输入窗长，也不等于系统只能每 219.775 μs 接一窗。流水线允许前后窗口的不同处理阶段同时运行。

### 4.6 指标五：数字 IQ 信号带宽，单位 MHz

它关注的是：

> 系统能够对多宽的数字基带频谱进行有效分析？

当前复数 IQ 的采样率为 160 MSPS，对应一个总跨度约 160 MHz 的数字频率区间，按常用居中表示约为：

~~~
−80 MHz ～ +80 MHz
~~~

准确地说，正频最高 FFT bin 小于 +80 MHz；界面上的 +80 MHz 是横轴范围的标注。

这里处理的是复数 IQ，不能把只针对单路实数信号的简单“正频范围 Fs/2”直接套过来，误认为整个 IQ 频谱跨度只有 80 MHz。

报告中 158.154297～158.593750 MHz，是特定满带测试子集测出的 99% 占用带宽范围：

- 它是实测输入的带宽结果。
- 它接近整个数字频谱跨度。
- 它不是外部模拟接收机的射频带宽。
- 它也不要求每个窄带信号都显示 158 MHz。

用一个 40 MHz 信号测试时，显示约 40 MHz 是正确方向，不能因为小于 158 MHz 就说系统不达标。

### 4.7 三组权衡

| 改什么 | 可能得到什么 | 同时要付出什么 |
| --- | --- | --- |
| 固定采样率，增加 FFT 点数 | 更细的 bin 间隔 | 更长观察时间、更多存储 |
| 固定 FFT 点数，提高采样率 | 更宽频谱跨度、更短窗时间 | bin 间隔变大，硬件时序更难 |
| 增加输入缓存 | 可以存更长的数据块 | 更多片上存储开销 |

当前设计是在吞吐、频谱范围、精细程度、延迟和器件资源之间取得的一个实际实现结果。

## 5. 系统内部如何分工

### 5.1 三个主要角色

| 部分 | 初学者理解 | 主要工作 |
| --- | --- | --- |
| PC 上位机 | 操作台和记录员 | 选数据、设参数、发命令、收结果、画图、存文件 |
| Zynq PS | 开发板里的处理器和管理员 | 网络通信、DDR 数据管理、DMA 控制、读取硬件结果 |
| Zynq PL | 开发板里的并行分析电路 | 回放、幅度统计、突发检测、FFT、频谱和带宽计算 |

Zynq 把处理器系统和可编程逻辑放在同一芯片上。

FPGA 可以理解为可按设计重新组织的数字电路。RTL 是描述这些电路行为、寄存器和连接关系的源代码。它不只是让电脑顺序执行的一份普通脚本。

### 5.2 连续动态更新路径

~~~
电脑准备 IQ
    |
    v
UDP 分块上传
    |
    v
PS 校验并暂存 DDR
    |
    v
AXI DMA 搬运
    |
    v
PL 非活动 Bank 装载、检查和提交
    |
    v
完整 FFT 窗口边界切换
    |
    v
活动 Bank 按 160 MSPS 回放
    |
    +----> 时域：原始 IQ 功率、幅度、突发长度 --------+
    |                                             |
    +----> 频域：FIFO、窗函数、FFT、功率谱、频点带宽 --+
                                                  |
                                                  v
                                 结果构建、编号检查、完整记录发布
                                                  |
                                                  v
                                      PS 读取 -> UDP -> 电脑显示和保存
~~~

普通桌面 GUI 的单文件采集，仍使用保留的寄存器访问路径装载并整块读回验证；专门的连续更新工具使用 DDR/DMA 双 Bank 路径。两者最终都由 PL 回放和分析，不能只因存在 DMA 就说每次 GUI 操作都经过 DMA。

### 5.3 Bank 是什么

Bank 在这里是一块 IQ 存储区。

项目有两个 Bank，每个最多保存 32768 对 IQ：

- 活动 Bank：正在为分析电路供数。
- 非活动 Bank：可以接收下一块数据。

类似两张轮换使用的工作台：一张正在加工，另一张准备下一份材料。

新数据只有通过长度、CRC 等检查，才有资格使用；切换发生在完整 FFT 窗口边界，避免一个窗口前半段来自旧数据、后半段来自新数据。

### 5.4 FIFO、DDR、DMA、BRAM 分别是什么

| 名称 | 可以怎样理解 |
| --- | --- |
| FIFO | 先进先出的排队缓冲，先进去的数据先出来 |
| DDR | 开发板上容量较大的工作内存，供 PS 和 DMA 使用 |
| DMA | 自动搬运数据的硬件，减少处理器逐字搬运 |
| BRAM | FPGA 芯片内部的专用存储块，适合稳定、高速的电路访问 |
| CRC | 根据数据计算的校验码，用于发现传输或装载内容损坏 |

输入 FIFO 为 4096 对 IQ，用于衔接处理节拍。缓冲容量有限，不能无限吸收后级长期处理不过来的数据。

### 5.5 为什么要做这么多完整性检查

只显示一个合理的频率，并不足以证明系统一直正确。

例如中间丢了样本、混用了窗口、结果没有收齐，某些数字仍然可能看起来正常。

因此项目还检查：

- 装载的数据与原文件是否一致。
- 窗口编号、配置编号是否对应。
- 发出、接受、FFT 输入、FFT 输出的样本数是否守恒。
- 有没有硬件错误、队列丢弃、记录缺口或 UDP 缺包。
- 停止后是否把流水线中的结果排完。

这些检查，是“连续高速处理”能被证据支持的重要部分。

## 6. 上位机每个区域是什么意思

### 6.1 顶部标题与状态

“数字 IQ 信号分析”和“Zybo Z7-20”说明当前程序及目标板卡。

右上角状态用于区分：

| 状态例子 | 含义 |
| --- | --- |
| 尚未采集／等待板卡数据 | 还没有本次板端测量 |
| 连接与装载中 | 正在建立通信、装载输入 |
| 正在接收板卡数据 | 本次分析正在运行并回传记录 |
| 采集结束／查看完整性结果 | 采集流程结束，应查看核验结果 |
| 离线查看／不连接板卡 | 正在看硬盘中的历史记录 |

“打开上位机成功”本身不代表“开发板已连接成功”。

### 6.2 输入 IQ 文件

这是准备送给板卡分析的数据文件路径。

点击“选择文件…”后，可以选 .bin 文件，程序会尝试绘制输入包络。

当前硬件正式采集只接受：

| IQ 点数 | 文件字节数 | 板内单次回放时间 |
| ---: | ---: | ---: |
| 16384 对 | 65536 B，64 KiB | 102.4 μs |
| 32768 对 | 131072 B，128 KiB | 204.8 μs |

文件必须是正确的小端交错 I16/Q16。

程序会按这个约定解释文件字节，并检查字节数、样本对数等结构条件；它不能自动辨认任意 .bin 原本的含义，也不会自动把其他编码转换成 IQ。一个长度刚好合法的错误文件，仍可能被按 IQ 读入，却得到没有意义的结果。

预览代码可以显示更短文件的包络，但“能预览”不等于“满足当前硬件装载长度”。开始采集时还会按板端 FFT 点数检查。

### 6.3 “选择文件…”

它只选择输入并绘制电脑计算的参考包络，不会因为选择文件就开始测量。

第一次选择文件后，上面有曲线、下面还没有频谱，是正常情况。

### 6.4 “打开已有记录…”

选择以前保存的一整个采集目录，在没有连接板卡时也可以查看结果。

它主要读取：

- frequency.bin 或 FREQ.BIN。
- burst.bin 或 BURST.BIN。
- capture.json 或 META.JSON。
- snapshot.json 或 SNAP.BIN。

它不是“重新对文件做一次硬件测量”。

如果历史记录中的原始 IQ 文件已经移动或缺失：

- 板端记录仍可显示。
- 输入包络可能无法显示。
- 程序不会拿另一份输入替代它。

### 6.5 板卡 IP

这是开发板网络接口的地址，默认：

~~~
192.168.1.10
~~~

它是板卡地址，不是电脑地址。原工程常用直连电脑地址为 192.168.1.20，子网掩码为 255.255.255.0；实际应与当前网络配置一致。

这里使用本地以太网通信，不要求互联网访问。USB 供电或 JTAG 连接也不能代替这条以太网数据链路。

### 6.6 “开始采集”

程序大致按以下顺序工作：

1. 检查持续时间、检测模式、门限等输入是否合法。
2. 读取 IQ 文件，检查字节数、样本对数等结构条件，并按约定的 I16/Q16 格式解释。
3. 连接板卡，读取硬件版本、采样率、FFT 点数等信息。
4. 检查板卡是否空闲。
5. 装载 IQ，并读回检查内容。
6. 下发配置，再读回确认配置。
7. 启动板内回放与分析。
8. 接收频域记录、突发记录和频谱快照。
9. 停止后等待结果排空。
10. 检查完整性并保存本次结果。

运行时多数配置被锁定，目的是保持“这次记录对应这一套参数”。

### 6.7 “窗口边界停止”

它请求板卡在完整 FFT 窗口结束处停止继续发样本，并等待已经进入流水线的数据处理完成。

它可以避免正常停止时只留下半个 FFT 窗口。

但是：

> 完整 FFT 窗口结束，不一定刚好是某段突发的自然结束。

所以即使使用这个按钮，最近突发仍可能带 CAPTURE_TRUNCATED。

关闭窗口时，如果程序还在采集，也会先请求停止并保存，而不是直接把进行中的采集丢掉。

### 6.8 四张结果卡片

| 卡片 | 大数字是什么 | 下方说明是什么 |
| --- | --- | --- |
| 信号幅度 | 最新频域记录对应窗口的 RMS，单位数字码值 | 同一窗口的峰值 |
| 帧长度 | 最近一条突发记录的持续时间，单位 μs | 该突发包含的 IQ 点数 |
| 频点 | 最新窗口的谱峰频率，单位 MHz | 提醒它是最高谱线 |
| 带宽 | 最新窗口的 99% 占用带宽，单位 MHz | 该带宽两端的中心位置 |

最重要的区别：

- 幅度、频点、带宽主要对应“最新 FFT 窗口”。
- 帧长度对应“最近一条突发记录”。

突发可能跨窗口，也可能不是最新频谱那一窗才产生的。因此，四张卡片不能一律理解为“同一段完整突发的全部属性”。

没有突发记录时，帧长度显示“—”，不是自动等于 0 μs。

### 6.9 卡片下方的一行状态说明

例如：

~~~
窗口 10 · 已收频域 11 / 突发 1 · PL 分析 219.78 μs · 标志 无
~~~

| 内容 | 含义 |
| --- | --- |
| 窗口 10 | 当前显示第 10 号 FFT 窗口，编号通常从 0 开始 |
| 已收频域 11 | 电脑已收到 11 条频域结果 |
| 突发 1 | 电脑已收到 1 条活动区间结果 |
| PL 分析 219.78 μs | 当前显示记录对应的板内分析延迟 |
| 标志 | 该频域记录附带的状态或异常提示 |

如果提示“包络未完整确认”，应查看突发起止状态和截断标志。

### 6.10 “波形与频谱”页

上图：装载 IQ 文件的包络。

- 横轴：这份输入文件按板内采样率回放时的时间。
- 纵轴：由 √(I²+Q²) 得到的幅度码值。
- 为了绘图效率，显示时会把一组输入点取最大幅度，不能用图上的一个绘制点当作一个原始 IQ 样本。
- 它来自电脑中的文件，不是板卡 ADC 实时回读，也不是两条原始 I、Q 曲线。

下图：硬件功率频谱。

- 横轴：数字基带频率，当前标成约 −80 到 +80 MHz。
- 纵轴：相对于本快照最高功率的 dB。
- 数据来自 PL 生成的 1024 点频谱快照。
- 快照由完整 16384 点频谱每 16 个 bin 取最大功率得到。
- 99% 带宽计算仍然使用完整频谱，不是拿这条显示曲线估算。

频谱图标题有自己的窗口号。它可能落后于顶部最新频域记录，比较时要核对编号。

#### dB 怎么理解

当前绘图大致使用：

~~~
相对 dB = 10 × log10(某点功率 ÷ 本快照最大功率)
~~~

| 图上数值 | 相对本快照最高功率 |
| ---: | --- |
| 0 dB | 一样强，是快照最高点 |
| −10 dB | 功率约为其 1/10 |
| −20 dB | 功率约为其 1/100 |

最高点每次都被归一化为 0 dB，所以两次采集的曲线都顶到 0 dB，不表示两次绝对幅度相同。比较实际强弱应同时看 RMS 和峰值。

图的显示范围约为 −100 到 0 dB，零功率点也会被画在显示底部。这不是已经测得并标定了 100 dB 的硬件动态范围。

### 6.11 “赛题指标”页

列名含义：

| 列名 | 意思 |
| --- | --- |
| 指标 | 正在比较哪一项要求 |
| 题面要求 | 比赛规定的数值门槛或单位 |
| 当前记录 | 从当前记录或采集元数据中读到的值 |
| 数值对照 | 该项数值是否达到界面列出的要求 |

运行中，延迟可能显示“本窗口”；采集结束并取得元数据后，会优先显示“本次最大”。

IQ 位宽这一行依据当前 I16/Q16 输入格式显示，并不是用模拟仪器测出的有效位数。

“数值满足”表示这张表的数值对照成立，不是单凭界面就完成全部正式验收。仍需看错误状态、样本守恒和测试证据。

带宽一行写“未规定数值下限”，是因为题面确实只给单位和优化方向。

### 6.12 “采集设置”页

这就是你截图中的页面，详细解释见下一章。

### 6.13 “数据与校验”页

有两个子页：

| 子页 | 用途 |
| --- | --- |
| 全部测量信息 | 用中文句子集中展示幅度、长度、频率、带宽、延迟、版本和核验结果 |
| 原始字段 / 元数据 | 用 JSON 展示原始记录和诊断信息，适合进一步核对 |

“复制完整数据”会复制当前中文测量说明及当前更新对象的原始字段。它不是把本次所有频域记录全部复制到剪贴板；完整历史在保存目录的 bin、json、csv 文件里。

这页尤其要看：

- 采集完整性。
- 数值参考核验及它的核验范围。
- UDP 缺包和硬件错误。
- 实际生效的门限。
- 突发起止位置及状态。
- 计数守恒。
- 构建 ID 和采样、时间戳时钟。
- 本次记录保存目录。

### 6.14 最底部状态栏

用来提示连接、装载、接收、保存及错误信息。

当前提交版在正常完成后可能把这条状态文字清空，而右上角显示采集完成。底部空白本身不代表出错，应结合“数据与校验”看最终状态。

界面更新和快照轮询大约是十分之一秒、半秒等量级的软件行为，实际还受网络和处理时间影响；GUI 消息队列也按约 150 ms 检查。

这些刷新时间与 6.25 ns 一个 IQ 点、160 MSPS 的硬件处理节拍完全不同。

## 7. 对照截图，逐项解释“采集设置”

### 7.1 先分两类参数

| 设置类别 | 影响什么 |
| --- | --- |
| 分析窗 rect/hann | 频谱计算前怎样对数据加权 |
| 循环回放、持续秒数 | 数据播放一次，还是反复播放多久 |
| 长度检测模式 | 用哪种规则找活动波形的起止点 |
| 零间隔确认 | digital-zero 的零背景确认规则 |
| 门限档位、策略、前导、四个手动值 | threshold 的能量判定规则 |

长度检测参数不会改变 FFT 点数和采样率。当前 160 MSPS、16384 点由板端工程配置决定，不是通过这些输入框临时改变。

### 7.2 分析窗：rect / hann

这里的“窗”是给每段 FFT 输入加权的方法，不是电脑窗口尺寸，也不是回放持续秒数。

#### rect：矩形窗

可以先理解成：

> 这一段中的每个样本都乘以 1，再做 FFT。

适合观察相干单音、做基本检查。相干单音可理解为信号在所截取时间段中恰好转过整数个周期。

如果截取边界不合适，频谱可能出现较明显的旁瓣和泄漏。

“泄漏”指一个频率的功率在有限长度 FFT 中分散到其他频点，不是网络漏包。

#### hann：Hann 窗

可以先理解成：

> 把这一段数据的两端轻轻压低，让截断处更平缓，再做 FFT。

形状大致为：

~~~
权重
1.0            /''''\
             /        \
0.0  ______/            \______
       窗口开始          窗口结束
~~~

好处是减弱旁瓣泄漏；代价是主瓣变宽。

“主瓣”就是一个主要频率附近的那座大峰，“旁瓣”是它周围较小的峰或拖尾。

#### 对本项目哪些测量有影响

| 项目 | 改 rect/hann 后怎样理解 |
| --- | --- |
| FFT 频谱 | 会改变 |
| 谱峰和占用带宽 | 可能改变，尤其非整数 bin、短突发、窄带输入 |
| 原始 IQ 窗口 RMS、峰值 | 计算支路不加窗，同一输入窗口不因 Hann 而被压低 |
| 包络长度 | 判定使用原始时域功率，不靠加窗后的样本 |
| FFT 点数、采样率 | 不改变 |

初学时可以先用 rect 检查已知单音、数字零突发，再用 hann 比较频谱变化。一般展示频谱可以使用 hann，但不能把它称为所有情况下都“更准确”。

### 7.3 循环回放

勾选：

~~~
文件开头 -> 文件末尾 -> 文件开头 -> 文件末尾 -> ...
~~~

取消勾选：

~~~
文件开头 -> 文件末尾 -> 停止供数 -> 排空并保存
~~~

GUI 这里循环的是当前同一个已装载文件，不会自动换成其他文件。

例如文件有 32768 对 IQ，一次只有 204.8 μs。循环 10 秒，就是反复播放这段短数据，期间不断生成新的分析窗口记录。

#### 文件连接处会影响测长

如果文件末尾和下一次文件开头都有足够零背景，检测器可以区分相邻突发。

如果整个文件都是非零单音：

~~~
第一次播放：████████
第二次播放：        ████████
连接后：    ████████████████
~~~

检测器看到的是连续活动，不会只因为文件回到开头就自动结束一条突发。

### 7.4 持续秒数（循环时）

例如填 10：

> 启动循环回放后，电脑约运行到 10 秒时发出停止请求。

随后板卡还需等完整 FFT 窗口结束，结果也要排空、传回并保存。因此，连接开始到界面全部完成通常不恰好为 10 秒。

合法范围：

~~~
大于 0，且不超过 3600 秒
~~~

可以填 1、2、10、0.5 等合法数值。

单次回放时，这个数不决定文件播放多久。但当前 GUI 仍会检查它是否合法，所以取消循环时也不要清空，保留 10 即可。

### 7.5 长度检测模式：digital-zero

它的判定基础是：

~~~
I = 0 且 Q = 0 -> 零样本
其他情况       -> 非零样本
~~~

它不是“接近零就算零”。

| 一对 IQ | 是否为数字零 |
| --- | --- |
| (0,0) | 是 |
| (1,0) | 否 |
| (0,−1) | 否 |
| (−20,15) | 否 |

适用输入：静默区明确由程序填成全零的数字文件。

不适合：背景持续存在非零噪声，却希望把这些噪声当作静默。噪声很小也通常不等于严格的零。

这种模式不会识别调制方式，只是在做严格零背景条件下的活动区间测量。

### 7.6 零间隔确认 / 点：截图中的 32

设为 32，表示需要连续观察到 32 对零 IQ，才确认前一段信号结束。

不是“只采集 32 点”，也不是“FFT 改成 32 点”。

~~~
情况 A：
活动 █████ -> 31 个零 -> 活动 █████
结果：中间间隔不够长，合成一段

情况 B：
活动 █████ -> 32 个零 -> 活动 █████
结果：间隔足够长，区分为两段
~~~

在 160 MSPS 下：

~~~
32 点 = 32 × 6.25 ns = 200 ns = 0.2 μs
~~~

合法值是 1～65535 的整数。

| 调整方向 | 通常意味着 |
| --- | --- |
| 增大 | 需要更长零间隔才分开，更容易合并相邻活动 |
| 减小 | 更短零间隔也能分开，更容易把内部短间隙拆成两段 |

#### 等待 32 点，不等于给长度加 32 点

正常结束后，长度终点回到“最后非零点的后一个位置”。用于确认的尾零不会计入正常活动长度。

但是，一段活动内部不足 32 点的零间隙会保留在长度和 RMS 平均区间中。

如果停止时只看到一部分尾零，还没等够 32 点，系统会标记截断，按已观察区间记录；此时尚未确认排除的尾零仍可能算在观察长度中。

#### 起点也需要背景确认

如果采集一开始就有信号，前面没有看到足够长的零背景：

> 系统不知道这段信号是否早在采集开始前就已经存在。

这种记录可能带 START_UNCONFIRMED。

前导零不足不会阻止记录活动；系统仍可输出观察区间，只是不能确认它包含了信号完整的起点。

### 7.7 长度检测模式：threshold

它根据“最近 16 点一共多强”判断开始和结束。

先计算每个样本的功率量：

~~~
p[n] = I[n]² + Q[n]²
~~~

再把最近 16 点相加：

~~~
S[n] = p[n] + p[n−1] + ... + p[n−15]
~~~

这里没有再除以 16。

你可以把 S 看成“一个滑动小篮子，里面装着最近 16 点的功率”。

- 新点进来。
- 最旧的点出去。
- 篮子总量随样本更新。

随后用两条门限和两种连续确认判断：

~~~
S 连续高于 ton，达到 kon 点 -> 确认开始
S 连续低于 toff，达到 koff 点 -> 确认结束
~~~

它适用于含有背景功率、不能依赖严格全零的输入。

它的边界会受滑动统计、噪声、门限和确认条件影响，所以不保证与原始文件的第一、最后非零样本严格重合。

### 7.8 ton：开启门限

可以读成“turn on 的门槛”。

当 S > ton，才具备开始条件。

调大，通常更不容易被弱噪声触发，但弱信号也更容易漏检；调小，弱信号更容易触发，也可能把背景当成信号。

它的单位是数字码值平方所构成的 16 点功率和，不是：

- 幅度码值本身。
- 伏特。
- dB。
- MHz。
- 采样点数。

稳定幅度为 A、窗口已经充满时，近似有：

~~~
S = 16 × A²
~~~

例如幅度 A=100 码时：

~~~
S ≈ 16 × 100² = 160000
~~~

所以不能把 ton=100000 理解成“幅度达到 100000 码”。

### 7.9 toff：关闭门限

当 S < toff，才进入结束判断。

通常让 toff < ton：

~~~
较低功率         中间缓冲区              较高功率
   < toff        toff ～ ton               > ton
可判断结束     保持已有状态更稳定       可判断开始
~~~

这叫启停迟滞：开始要求较强，结束要求已经降得较低，减少临界附近反复开关。

调大 toff，会更容易满足“低于关闭门限”，可能更早进入结束候选；调小则更难结束，也可能把更多尾部或背景并入。

注意：toff 仍然必须小于 ton。

### 7.10 kon：开启确认点数

不是只要一个样本高于门限，就立即确认有一段信号。

例如 kon=8，表示连续 8 个检测样本都满足开启条件，才确认开始。

在 160 MSPS 下，8 点对应 0.05 μs；这是连续确认长度对应的时间，不是整条分析流水的总延迟。

调大：

- 更不容易被极短的高能量干扰触发。
- 过短的真实信号也可能来不及确认。

调小：

- 更快确认。
- 对短时干扰更敏感。

### 7.11 koff：关闭确认点数

例如 koff=32，表示连续 32 个检测样本满足关闭条件，才确认结束。

如果中途信号恢复，系统会把暂存的低功率尾段合回原活动区间，避免一个小低谷把信号拆成两段。

调大：

- 对短暂跌落更宽容。
- 需要更久才能确认结束，也可能合并相邻信号。

调小：

- 更快确认结束。
- 更容易因短暂低谷而拆段。

#### 不要机械地把 kon、koff 加到测长结果上

开始确认后，系统保留候选起点；结束确认后，系统使用候选终点，并排除确认尾段。

因此，“koff=32”不等于“测量长度必然多 32 点”。

16 点滑动功率本身仍会造成边界响应偏移。报告中的一个特定门限用例尾边界相对设计终点晚 15 点，就是这一类现象。

### 7.12 门限档位：legacy / robust

这两个英文词代表两组参数预设，不是两种新的 FFT 算法。

| 档位 | 含义 | 默认 kon | 默认 koff |
| --- | --- | ---: | ---: |
| legacy | 原有基线档位，便于沿用和比较 | 8 | 32 |
| robust | 为带噪输入提供的另一组预设 | 16 | 8 |

如果策略是 quiet-prefix，还会有不同的背景倍数：

| 档位 | ton 对背景 16 点能量的倍数 | toff 的倍数 |
| --- | ---: | ---: |
| legacy | 4 | 2 |
| robust | 3 | 1.75 |

robust 不表示“任何噪声都能解决”，也不表示“永远比 legacy 更准确”。它只是另一组取舍。

当前 GUI 有联动：

- 选 robust，会自动把门限策略改为 quiet-prefix。
- 选 legacy，会自动把策略改为 fixed。

切换档位不保证清掉你之前手填的四个覆盖值。应检查有没有旧值仍在覆盖预设。

### 7.13 门限策略：fixed

fixed 的意思是“固定”。

采用固定门限，或者使用你手动输入的门限。当前：

~~~
threshold
legacy + fixed
ton、toff、kon、koff 全部留空
~~~

实际使用：

| 参数 | 实际值 |
| --- | ---: |
| ton | 1048576 |
| toff | 262144 |
| kon | 8 |
| koff | 32 |

对于稳定、已经充满 16 点篮子的恒包络：

- ton 大致对应幅度 256 码附近。
- toff 大致对应幅度 128 码附近。

比较是严格的大于、小于，且边界还有滑动和确认过程，所以这不是“碰到 256 码必然立即开始”的精确规则。

fixed 下，“前导静默点数 1024”不用于计算门限。

### 7.14 门限策略：quiet-prefix

可以翻译成：

> 用输入文件开头的一段已知纯背景，估计背景功率，再设置门限。

这是用户对输入的一个声明：

> 我知道文件开头这些点没有目标信号，只有背景。

它不是程序自动找到文件中最安静的位置。

计算过程是：

1. 电脑读取输入文件的前若干点。
2. 计算这段背景的平均 I²+Q²。
3. 换算成 16 点功率和。
4. 乘以当前档位的开启、关闭倍数。
5. 将结果下发给硬件。

门限是在开始采集前由电脑计算的，采集中不会因此自动追踪整个输入的噪声变化。

例如已知前导背景平均功率为 10000，选择 robust：

~~~
背景 16 点能量 ≈ 16 × 10000 = 160000
ton ≈ 160000 × 3 = 480000
toff ≈ 160000 × 1.75 = 280000
kon 默认 16
koff 默认 8
~~~

程序使用向上取整，还保证 ton 至少为 2、toff 至少为 1，且 toff 小于 ton。

这个最小值处理，是为了全零前导时仍可以使用严格比较确认背景。

### 7.15 前导静默点数：截图中的 1024

在 quiet-prefix 策略下，1024 表示：

> 用文件最开头的 1024 对 IQ 估计背景。

在 160 MSPS 下，对应 6.4 μs。

合法要求：

- 必须是整数。
- quiet-prefix 时至少 16 点。
- 不能超过输入文件总点数。
- 这段中应确实没有目标活动信号。

“前导静默”可以含有背景噪声，并不要求所有 IQ 都为零；它与 digital-zero 的严格全零是不同概念。

如果前 1024 点实际上已经有目标信号，程序会把信号的一部分也当成背景，估计出不合适、可能过高的门限。

当前 GUI 即使使用 fixed 或 digital-zero，也会先把该框解析成整数。因此不使用它时保持 1024 即可，不要清空或填文字。

### 7.16 ton/toff/kon/koff 留空，到底表示什么

留空表示：

> 没有手动覆盖，采用档位和策略最终计算的值。

它不等于 0，也不等于不做检测。

| 配置 | 四项留空时的含义 |
| --- | --- |
| threshold + legacy + fixed | 使用 1048576 / 262144 / 8 / 32 |
| threshold + legacy + quiet-prefix | ton/toff 按背景的 4/2 倍计算，kon/koff 为 8/32 |
| threshold + robust + quiet-prefix | ton/toff 按背景的 3/1.75 倍计算，kon/koff 为 16/8 |
| digital-zero + legacy + fixed | 不手动覆盖门限，按数字零规则测长 |

真正用上的值，可以在“数据与校验”的“实际门限”中查看。

注意：digital-zero 时即使元数据仍记录了一组门限数值，也不表示这些数值参与了数字零边界判断。

### 7.17 哪些组合允许，哪些会报错

| 长度模式 | 门限档位 | 策略 | 手动 ton/toff | 是否允许 |
| --- | --- | --- | --- | --- |
| digital-zero | legacy | fixed | 全部留空，kon/koff 也留空 | 允许，截图所用状态 |
| digital-zero | robust | 任意 | 任意 | 不允许 |
| digital-zero | legacy | quiet-prefix | 任意 | 不允许 |
| digital-zero | legacy | fixed | 四项手动值中任一项非空 | 不允许 |
| threshold | legacy | fixed | 都留空 | 允许 |
| threshold | legacy | fixed | ton/toff 两个一起填 | 允许 |
| threshold | legacy | fixed | 只填 ton 或只填 toff | 不允许 |
| threshold | legacy | quiet-prefix | ton/toff 留空 | 允许，需要真实纯背景前导 |
| threshold | robust | quiet-prefix | ton/toff 留空 | 允许，需要真实纯背景前导 |
| threshold | robust | fixed | 任意 | 不允许 |
| threshold | legacy 或 robust | quiet-prefix | 手填 ton 或 toff | 不允许，避免两种门限来源冲突 |

threshold 模式下，kon、koff 可以分别单独覆盖，只要数值合法。

当前 GUI 的数字规则：

| 输入项 | 合法形式 |
| --- | --- |
| 持续秒数 | 大于 0、不超过 3600 的数值，可有小数 |
| 零间隔 | 1～65535 的整数 |
| 前导静默 | 整数；quiet-prefix 下为 16～文件总点数 |
| ton/toff | 留空或十进制整数，且 0 ≤ toff < ton < 2^36 |
| kon/koff | 留空或 1～65535 的整数 |

GUI 直接用十进制整数解析手动项，不要填写“8点”“0.2μs”“0x100”这类带单位或十六进制形式。

toff=0 虽能通过合法性检查，但能量不小于 0，无法满足严格的 S<0。因此它不能通过正常关闭门限确认结束，只能等停止截断或长度上限分段。初学者不要把 toff 设为 0。

### 7.18 切换 digital-zero 时，程序实际做了什么

从下拉框选择 digital-zero 时，程序会：

1. 把门限档位设回 legacy。
2. 把策略设回 fixed。
3. 清空 ton、toff、kon、koff 四项。

它不会把高级框从页面上移走，所以你仍然能看到这些选项。

不要因此以为“数字零模式下随便改高级值也会忽略”。如果切换后再选 robust、quiet-prefix，或者重新手填四个门限覆盖值之一，当前程序会在开始时拒绝这些不适用的组合。

切回 threshold 后，被清空的手动门限不会自动恢复。

### 7.19 零间隔 32 和 koff=32 有什么区别

| 项目 | 零间隔确认 32 | koff=32 |
| --- | --- | --- |
| 对应模式 | digital-zero | threshold |
| 判断对象 | 连续 I=Q=0 | 连续 16 点滑动功率低于 toff |
| 能否容忍非零背景 | 本身不能把非零噪声当零 | 可以结合门限判断 |
| 点数对应时间 | 32 点约 0.2 μs | 32 次连续判定对应约 0.2 μs |
| 是否意味着长度多加 32 点 | 不是 | 不是 |

数字刚好相同，但算法含义不同。

## 8. 你这张截图，完整翻译成一句话

截图当前选择为：

| 项目 | 截图的值 | 本次含义 |

| 分析窗 | hann | 频域分析使用 Hann 加权 |

| 持续秒数 | 10 | 循环启动后约 10 秒发出停止请求 |
| 长度检测模式 | digital-zero | 根据严格全零背景找活动区间 |
| 零间隔确认 | 32 | 连续 32 对零 IQ 确认结束 |
| 门限档位 | legacy | 保持数字零模式要求的兼容状态 |
| 门限策略 | fixed | 同上，不代表本次采用门限检测 |
| 前导静默 | 1024 | 本次不参与数字零测长，保持合法整数 |
| ton/toff/kon/koff | 留空 | 不手动覆盖 threshold 参数 |

把它读成：

> 把选定的同一个 IQ 文件装入板卡，按 160 MSPS 反复回放；约运行 10 秒后，请求在完整 FFT 窗口边界停止。每 16384 对 IQ 做一次 Hann 窗频谱分析；与此同时，用数字零模式测活动包络，连续 32 对全零 IQ 才确认上一段结束。

这里的三件事要分开：

| 数字 | 管什么 |
| --- | --- |
| 10 秒 | 这次循环实验运行多久 |
| 16384 点 / 102.4 μs | 每次 FFT 看多长的一段输入 |
| 32 点 / 0.2 μs | 数字零检测需要多长零间隔来确认结束 |

还要看你选的是什么文件：

- 文件有明确全零前导和尾部：适合确认突发长度。
- 文件全程是连续非零单音：适合看幅度和频率，但没有自然结束的完整突发。
- 文件背景有非零噪声：digital-zero 通常不适合把背景与信号分开。

截图里的 digital-zero 是当前选定状态；程序刚打开时，初始化默认长度模式实际是 threshold。

## 9. 三个可以照着做的入门练习

以下练习是说明步骤，本文编写时没有执行上板或重新采集。

前提：开发板已经运行与本工程配套的网络程序，电脑与板卡网络配置正确。

上位机启动入口：

[打开本项目上位机](<../Open_IQ_Monitor.cmd>)

双击这个启动文件，是启动电脑程序；不会自动替你向开发板烧录或更新启动镜像。

### 9.1 练习一：测一段跨窗口的 512 点突发

选择：

[short512_boundary.bin](<../data/replay_vectors/short512_boundary.bin>)

这个文件有 32768 对 IQ，明确的非零区间为：

~~~
[16128, 16640)
~~~

按以下设置：

| 参数 | 填什么 |
| --- | --- |
| 分析窗 | rect |
| 循环回放 | 取消勾选 |
| 持续秒数 | 保持 10，不清空 |
| 长度检测 | digital-zero |
| 零间隔确认 | 32 |
| 门限档位 / 策略 | legacy / fixed |
| 前导静默 | 保持 1024 |
| 四个手动门限项 | 全部留空 |

开始采集并完成后，重点看：

1. 文件长 32768 点，通常应有两个完整频域窗口记录。
2. 活动区间跨过第 16384 点，但应是一条 512 点突发。
3. 长度换算为 512/160=3.2 μs。
4. 最近突发的起点、终点应与已知区间核对。
5. 没有截断或起点未确认，才可按完整活动长度解释。
6. 查看“采集完整性”和“数值参考核验”的结论及范围。

此处的长度参考通过，检查的是数字零突发的区间、标志、能量、峰值和 RMS，不等于自动逐点验证全部 FFT。

你会看到：一个文件、两个 FFT 窗、一个突发，是完全可以同时成立的。

### 9.2 练习二：比较同一突发的两种测长模式

选择：

[burst_fs4.bin](<../data/replay_vectors/burst_fs4.bin>)

这个文件明确的非零区间是：

~~~
[2048, 26624)
长度 24576 点
时间 24576 ÷ 160 = 153.6 μs
~~~

先按练习一使用 digital-zero，观察完整数字零活动区间。

再另开一次采集，设置：

| 参数 | 值 |
| --- | --- |
| 长度检测 | threshold |
| 门限档位 | legacy |
| 门限策略 | fixed |
| ton/toff/kon/koff | 留空 |
| 循环 | 初次仍取消 |

比较两次起点、终点和长度。

如果门限模式的边界有一些点数差异，先看 16 点滑动能量和门限的响应，不要立刻认定硬件出了问题。两种检测本来就使用不同的活动定义。

### 9.3 练习三：只看一个已知单音的频率和窗函数差异

选择：

[tone_pos_fs4.bin](<../data/replay_vectors/tone_pos_fs4.bin>)

在当前 160 MSPS 配置下，Fs/4 对应：

~~~
160 MHz ÷ 4 = +40 MHz
~~~

本练习长度模式选 digital-zero，零间隔 32，高级保持 legacy/fixed、四项留空。先单次、rect，查看谱峰是否在 +40 MHz 附近；再另采一次换 hann，比较频谱主瓣与 99% 带宽。

你可能观察到：

- 谱峰仍位于 +40 MHz。
- 两次原始 IQ 的 RMS、峰值相同或保持相同统计口径。
- rect 的单音带宽可能为 0。
- hann 的单音带宽可能为约 0.019531 MHz。
- 文件没有自然的前后静默，长度记录可能带起点未确认和停止截断。

这一练习主要验证频率、幅度和窗函数含义，不适合拿连续单音的截断长度证明完整帧长。

负频单音也有对应文件：

[tone_neg_fs4.bin](<../data/replay_vectors/tone_neg_fs4.bin>)

其当前基带频率对应 −40 MHz。

### 9.4 如果要尝试带噪测长

只有当你明确知道文件开头一段没有目标信号时，才使用：

~~~
长度检测：threshold
门限档位：robust
门限策略：quiet-prefix
前导静默：填写真实已知的纯背景长度
ton/toff：留空
kon/koff：初次留空
~~~

先比较检测到几段、有没有漏检或误检，再看起止误差。

不要因为选项叫 robust，就直接声称任何 SNR 都能正确测长。归档的所测 0 dB 条件仍有漏检，10 dB 和 20 dB 也只能说明各自已测试用例的结果。

## 10. 怎样读一组测量结果

### 10.1 建议按这个顺序看

1. 先确认输入文件是什么，是否与你想测的信号一致。
2. 确认单次/循环、窗函数和长度模式。
3. 看采样率、FFT 点数和构建 ID，知道使用哪版硬件。
4. 看“采集完整性”，排除样本或记录丢失。
5. 看标志，区分正常测量、分辨率限制和截断。
6. 再解释四张卡片。
7. 核对当前窗口、突发区间和频谱快照的窗口号。
8. 有已知真值时，再比较数值误差。

只看顶部大数字，很容易忽略“记录来自哪一段数据”和“这段记录是否完整”。

### 10.2 用已经准备过的演示信号理解结果

下表概述 PPT 中的几类案例。这里引用的是既有归档，不表示本文编写时重新上板。

| 输入例子 | 主要展示什么 | 读结果时注意 |
| --- | --- | --- |
| +20 MHz 单音，幅度在两窗间约从 4096 变 12288 | 窗口 RMS 对幅度阶跃有响应 | 卡片一般显示最新一窗，比较两窗要看完整记录 |
| −30 MHz 与 +20 MHz 双音 | 能看见正、负频率两座峰 | 顶部只显示更强的 −30 MHz 谱峰 |
| −50 到 +50 MHz 线性扫频 | 功率分布在一片宽频带 | 既有矩形窗例子的 99% 带宽约 98.769531 MHz |
| [12288,20480) 的跨窗突发 | 包络测长不被 FFT 边界切开 | 8192 点，即 51.2 μs |
| 约 −20 到 +20 MHz 的窄 OFDM | 较窄的宽带信号 | 既有 Hann 例子的 99% 带宽约 39.511719 MHz |
| 约 −70 到 +70 MHz 的宽 OFDM | 更宽的功率分布 | 既有 Hann 例子的 99% 带宽约 138.330078 MHz |
| 窄 OFDM 整体移频 +25 MHz | 中心位置改变，宽度大致保持 | 既有带宽中心约 +24.990234 MHz，谱峰不必在中心 |
| 含噪突发 | 门限检测和边界误差 | 所测 10 dB 例子中一段长度比真值多 10 点，即 0.0625 μs |

实际结果以对应文件、窗函数、窗口号和原始记录为准，不要拿这个表去要求任意同名信号都精确得到同一个数字。

### 10.3 为什么跨窗突发的窗口 RMS 与突发 RMS 不一样

PPT 的跨窗例子：

~~~
文件 32768 点，分成两个 FFT 窗口：

窗口 0： [0 ......................... 16384)
窗口 1：                              [16384 .................. 32768)

活动区间：            [12288 .................. 20480)
                          4096 点     4096 点
~~~

每个窗口只有 4096/16384=1/4 的点处于活动状态。

如果活动幅度约为 8192：

~~~
每窗 RMS ≈ 8192 × √(1/4) = 4096
活动区间 RMS ≈ 8192
活动长度 = 8192 点 = 51.2 μs
~~~

所以顶部窗口 RMS 为 4096，详细信息中的突发 RMS 为 8192，可以同时正确。

### 10.4 为什么长度显示 204.80 μs，却不能说有一帧完整的 204.80 μs

32768 点文件单次回放时间刚好是：

~~~
32768 ÷ 160 = 204.8 μs
~~~

如果文件从头到尾都是活动信号，系统可能记录整个观察区间，但起点或终点没有自然背景确认。

此时：

- 数字反映了观察长度。
- 不证明信号原本恰好这么长。
- 应同时查看 START_UNCONFIRMED、CAPTURE_TRUNCATED 等标志。

### 10.5 为什么循环 10 秒时会出现约 6.5536 ms 的长度段

当前上位机把最大活动段长度配置为：

~~~
1048576 点
~~~

换算时间：

~~~
1048576 ÷ 160 = 6553.6 μs = 6.5536 ms
~~~

持续不结束的活动达到上限后会分段，并带 DETECTOR_TIMEOUT。

这不是网络连接“等了 6 ms 超时”，也不是 GUI 忽略了 10 秒设置。

- 10 秒：整次循环实验的持续时间。
- 6.5536 ms：单条活动区间的最大段长。
- 219.775 μs：一个 FFT 窗口的最大分析延迟。

三者约束不同对象，不相互矛盾。活动信号可以长于 2 ms，同时系统仍按窗口持续产生满足 2 ms 要求的频域结果。

### 10.6 几种常见输入名称

| 名称 | 零基础理解 | 本项目主要看什么 |
| --- | --- | --- |
| 单音 tone | 一个主要频率的测试信号 | 幅度、正负频点、窗函数 |
| 双音 dual | 两个单音相加 | 多峰、强弱和频谱分布 |
| chirp | 频率随时间逐渐扫过一段范围 | 扫过频带的功率分布 |
| QPSK | 用四种相位状态承载数字信息的示例 | 幅度、包络、带宽；当前不解码数据 |
| OFDM | 多个子载波同时承载信息 | 宽带分布、中心频移、峰值与 RMS |
| DC | 不随时间变化的 I/Q 分量 | 直流频点、满幅等边界检查 |
| noise | 随机起伏的输入或背景 | 带宽和检测边界 |

普通一窗 FFT 告诉你这一窗里哪些频率有功率，不能仅凭这张图看出 chirp 先扫低频还是先扫高频。要看扫频先后顺序，通常需要时频图或其他分析；当前界面没有把普通频谱当成时频图。

## 11. “校验通过”和状态标志怎么理解

### 11.1 采集完整性通过

它主要检查：

- 窗口数量与输入点数能否对应。
- 记录编号是否完整。
- 结果是否收到足够数量。
- UDP 结果包是否存在缺口。
- 硬件有没有报告错误。
- 配置和模式是否与记录一致。
- 延迟是否满足检查要求。
- 支持诊断时，各阶段样本计数是否守恒。

它解决的是：

> 这次采集和传输有没有明显遗漏或混乱？

它不自动解决：

> 每一个频谱值与独立数学参考是否完全一样？

### 11.2 数值参考核验通过

这表示另外使用参考模型检查了规定范围内的数值。

普通 GUI 中：

| 操作 | 自动数值参考行为 |
| --- | --- |
| 单次 + digital-zero | 核对数字零突发区间、标志、能量、峰值和 RMS |
| 循环 + digital-zero | 普通采集流程通常显示未执行独立数值参考 |
| threshold 普通采集 | 普通采集流程通常显示未执行独立数值参考 |

即使“单次数字零参考通过”，也不能把它扩展成“本次所有 16384 个 FFT 点和全部频域参数都自动逐点核对通过”。

项目另有完整核心仿真和专门实板验证脚本，用于更全面的比较。

“未执行”不是“失败”，而是程序诚实地说明本次没有做这一项独立比较。要同时看状态和核验范围。

### 11.3 样本守恒

停止并排空后，正常情况下应有：

~~~
源发出样本数
= 输入 FIFO 接受样本数
= FFT 输入样本数
= FFT 输出样本数
= 本次实际输入样本数
= FFT 点数 × 完成窗口数
~~~

这相当于一条加工线：

> 送进去多少原料、接收多少、加工多少、产出多少，最后能够对账。

运行中各计数可能是在不同瞬间取得，不能要求任何一次界面读取都严格同步。最终守恒应在停止、排空后检查。

“结果队列拒绝”与“输入样本拒绝”也要分别看：前者可能是记录存不下，后者可能是输入未被接收。

### 11.4 频域的提示标志

| 标志 | 中文解释 | 应怎样读 |
| --- | --- | --- |
| NO_POWER | 所选分析范围内功率为零 | 不能把此时给出的零频率当成检出一个正常直流信号 |
| RESOLUTION_LIMITED | 上下带宽边界落在同一个 bin | 带宽可能输出 0，表示受离散频率格子限制 |
| EDGE_RISK | 带宽边界碰到分析范围边缘 | 应检查信号是否越出范围，或范围是否截掉了功率 |
| FFT_OVERFLOW | FFT 定点运算报告溢出 | 该数值不能忽略此状态后直接当正常结果 |
| SOURCE_GAP | 输入出现未正常接收的样本 | 检查输入完整性 |
| METADATA_ERROR | 窗口上下文或相关元数据不一致 | 不能放心把时域和频域当成同一窗口 |
| RESULT_LOSS_SEEN | 检测到结果丢失 | 检查队列、传输和记录数量 |

NO_POWER、RESOLUTION_LIMITED、EDGE_RISK 的意义不同，并不是所有标志都代表程序崩溃。

### 11.5 突发长度的常见标志

| 标志 | 意思 | 能否直接当完整自然突发长度 |
| --- | --- | --- |
| DIGITAL_ZERO | 使用数字零模式 | 它本身不是错误，仍需看其他标志 |
| START_UNCONFIRMED | 起点前没有观察到足够背景，或为强制分段后的续段 | 不能确认完整起点 |
| CAPTURE_TRUNCATED | 停止时尚未确认自然结束 | 不能确认完整终点 |
| DETECTOR_TIMEOUT | 达到最大段长而分段 | 是长度上限分段，不能当自然结束 |
| CONFIG_ABORT | 配置或中止相关的完整性状态 | 应按对应记录检查，不直接称完整帧 |

结果格式还定义了 PARTIAL_WINDOW、LENGTH_OR_COUNTER_OVERFLOW 等状态名，用于不完整窗口、长度或计数异常等诊断。不是每个名字都会在当前正常 GUI 流程中触发；遇到时应结合原始字段和日志解释。

### 11.6 没有长度记录不一定出错

帧长度显示“—”，可能是：

- 输入全零，没有活动段。
- 正在活动，还没有确认结束。
- 信号太弱，没达到门限。
- 背景并非全零，却选择了 digital-zero。
- 前后活动没有足够间隔，被合并。
- 当前记录尚未传到电脑。

应先看输入和检测参数，再判断是否异常。

### 12.3 频域窗口记录

| 字段 | 中文含义 |
| --- | --- |
| first_sample | 这个窗口第一个样本在本次连续数据中的位置 |

| done_tick | 板内分析结果生成时的时间戳 |
| latency_cycles | 分析延迟，单位硬件时钟拍 |
| latency_us | 换算成 μs 的分析延迟 |
| fft_length | 本窗 FFT 点数，当前为 16384 |
| peak_hz | 最大谱峰的频率 |
| low_hz | 99% 占用带宽下边界频率 |
| high_hz | 99% 占用带宽上边界频率 |
| bandwidth_hz | 99% 占用带宽宽度 |
| bandcenter_hz | 两边界的中心频率 |
| q_peak | 谱峰对应的居中频率索引 |
| q_low / q_high | 带宽边界对应的索引 |

| total_spectrum_power | 分析范围内 FFT 功率总和，属于内部定点量 |
| peak_spectrum_power | 最大频点的 FFT 功率，属于内部定点量 |
| raw_energy | 这个窗口原始 I²+Q² 的累计值 |
| window | 采用 hann 还是 rect |

tick 是硬件时钟拍，不是北京时间。当前时间戳时钟为 160 MHz，一拍为 6.25 ns。

q_peak、q_low、q_high 是频率尺上的格子编号，不是 Hz。当前常用换算为：

~~~
频率 ≈ (q − 8192) × 160000000 ÷ 16384
~~~

最终 Hz 字段会按程序规则舍入为整数，因此不要拿显示的小数位数推断实际分辨能力。

内部 FFT 功率量还与 FFT 缩放、加窗和定点格式有关，不能直接拿 total_spectrum_power 当瓦特，或把它与原始时域 raw_energy 不加换算地当作相同数值。

### 12.4 突发记录特有字段

| 字段 | 中文含义 |
| --- | --- |
| detector_mode | threshold 或 digital-zero |

| start_confirmed | 是否确认了完整起点 |

### 12.5 频谱快照字段

| 字段 | 含义 |
| --- | --- |
| window_id | 这一张快照属于哪个 FFT 窗口 |

~~~

~~~

因此，快照显示的点数和图上尖峰的宽度，不能替代完整 FFT 的单 bin 精度。

## 13. 结果保存在哪里，常见问题怎么处理

### 13.1 保存目录

普通 GUI 会在它所在的工程根目录下，自动新建：

~~~
captures/日期_时间_后缀/
~~~

本文对应工程的实际保存父目录：

`captures/`（运行采集后自动生成）

完整本次子目录会显示在“数据与校验”中。使用另一份工程副本启动上位机，结果就保存在那份工程自己的 captures 下。

### 13.2 每个文件的用途

| 文件 | 内容 | 建议怎样看 |
| --- | --- | --- |
| frequency.bin | 每条 128 字节的板端窗口原始记录 | 留作原始证据，用工具解码 |
| frequency.json | 解码后的全部窗口结果 | 按字段检查或用于程序处理 |
| frequency.csv | 相同窗口数据的表格形式 | 用 Excel 等查看每一窗 |
| burst.bin | 每条 64 字节的突发原始记录 | 留作原始证据 |
| burst.json / burst.csv | 全部突发结果 | 查看每段起止、长度和标志 |
| capture.json | 输入、参数、版本、计数及核验结论 | 排查问题最重要的文件之一 |
| snapshot.bin | 最近一张硬件功率快照 | 留作原始数据 |
| snapshot.json | 快照窗口号和 1024 个功率值 | 核对图与窗口的关系 |
| 结果说明.md | 自动生成的摘要及前最多 64 条窗口结果 | 快速了解本次采集 |

有些情况没有取得可用快照，就不会生成快照文件。没有突发时，突发记录可能为空。

自动“结果说明”只展示部分窗口，不代表剩下的窗口没保存；完整数据看 JSON、CSV、BIN。

### 13.3 离线打开后的显示范围

“打开已有记录”默认显示：

- 最后一条频域记录。
- 最后一条突发记录。
- 保存的那一张频谱快照。
- 对应元数据。

它不会自动把所有历史窗口按电影方式回放，也没有把每一窗都做成可拖动的历史浏览器。

如果要比较幅度阶跃的窗口 0 和窗口 1，应打开 frequency.csv 或 frequency.json。

### 13.4 常见问题

| 现象 | 先怎样理解或检查 |
| --- | --- |
| 程序打开了，但没有测量值 | 是否点了开始；板卡是否运行配套程序；网络是否连通 |
| 输入有包络图，下方没有频谱 | 包络是本地预览；板端可能还没采集，或没有取得快照 |
| 选择文件能预览，开始时报长度不对 | 当前硬件正式采集需要 16384 或 32768 对 IQ |
| “No command reply…” | 检查板卡程序、板卡 IP、以太网线和本机网卡配置 |
| “Board is already running…” | 板卡可能仍由前次采集或另一控制程序使用；应先正常停止，不要同时开多个控制端 |
| 更改门限时报配置错误 | 查第 7.17 节的合法组合；尤其 robust/fixed、只填一个门限、quiet-prefix 手填 ton |
| 数字零模式一直没有正常结束 | 输入是否真的有连续全零背景，而不是小幅噪声 |
| 循环单音显示很多超长段 | 输入连续活动，达到最大段长后分段，不是自动存在很多真实通信帧 |
| 数值参考显示“未执行” | 本次没有运行对应独立参考，不等于采集失败 |
| 顶部窗口号与频谱标题不同 | 卡片更新和快照更新不同步，应按各自编号解读 |
| 两次频谱都顶到 0 dB | 每张图单独归一化，绝对强弱应比较 RMS 和峰值 |
| 带宽是 0，但明显有单音 | 可能上下边界在一个 bin，查看 RESOLUTION_LIMITED |
| 出现 EDGE_RISK | 检查频谱是否接近或碰到分析范围边缘 |
| 数字显示很多小数位 | 这是显示格式，不等于相同数量的有效精度 |
| 离线结果有数字，没有上方包络 | 原始 IQ 文件可能不可用，记录本身仍可查看 |
| 开始到完成远大于 219.775 μs | 总操作还包括上传、验证、网络、排空、导出和界面处理 |

## 14. 这个项目的实际技术工作与验证内容

### 14.1 FFT 内核与项目外围电路的区别

FFT 数学变换使用 AMD FFT IP。

IP 可以理解为厂商提供、可配置的电路模块。使用它仍然需要正确配置、提供数据、处理握手、定点缩放、索引和异常，并把它融入完整系统。

项目主要自主组织的部分包括：

- IQ 装载、校验和 Bank 管理。
- 窗函数及定点预处理。
- 时域幅度、能量和活动区间统计。
- 功率谱存储、谱峰与占用带宽扫描。
- 结果换算、编号关联、记录缓存与发布。
- PS 应用固件、上位机和测试工具。
- 系统集成、时钟、复位、跨域与实现优化。

不能把整个项目等同于 FFT IP 本身，也不能反过来把 AMD FFT 内核说成从零设计的自研 FFT。

### 14.2 几个关键实现为什么有价值

| 实现 | 解决的问题 |
| --- | --- |
| 双 IQ Bank | 当前块分析与下一块准备可以重叠 |
| 窗口边界切换 | 防止一窗混入新旧两块数据 |
| 单份完整功率谱 + 延迟写队列 | 减少保存两份全谱的存储开销，同时保护旧窗扫描 |
| 八路扫描、分级前缀累加 | 加快全谱累计，又保留单 bin 边界 |
| Hann 四分之一系数重构 | 用 4096 项恢复 16384 点系数序列 |
| 原始 IQ 与频域分支分开 | 幅度、长度不被窗增益和 FFT 缩放混淆 |
| 共享数学单元 | 不必给每个样本配置开方、除法电路 |
| RMS 保留商和余数 | 降低变长区间直接整除的截断损失 |
| DMA 提交、ACK 分阶段 | 缩短控制长路径，保持事务一致性 |
| 整条记录写完再发布 | 避免软件读到写了一半的结果 |
| 样本和记录对账 | 为连续处理和完整性提供证据 |

“四分之一系数”是系数表项数减少 75%，不是整个系统 BRAM 减少 75%。

输入侧“双 Bank”与频域侧“单份共享谱”不是相互矛盾：它们缓存的是不同对象。

### 14.3 帧间流水重叠，不等于输入窗口重叠

当前基础窗口可理解为：

~~~
窗口 0：样本 0～16383
窗口 1：样本 16384～32767
窗口 2：样本 32768～49151
~~~

它们是相邻、互不重叠的输入区间。

“不同帧的输入、计算、输出可以重叠”，指的是流水线各阶段在同一时刻处理不同窗口：

~~~
同一时刻：
前级在接窗口 2
中间在处理窗口 1
后级在输出窗口 0
~~~

不能据此说当前实现一定用了 50% 重叠的滑动 FFT 分窗。

### 14.4 资源和时序结果

当前完整设计的归档实现结果：

| 项目 | 数量或结果 |
| --- | --- |
| LUT | 22708，约 42.68% |
| FF | 28413，约 26.70% |
| 等效 BRAM36 | 128，约 91.43% |
| DSP | 49，约 22.27% |
| 工作时钟 | 160 MHz |
| 最差建立时间裕量 | +0.007 ns |
| 最差保持时间裕量 | +0.050 ns |

初学者可以这样理解：

- LUT：实现一般逻辑运算。
- FF：保存一拍一拍的状态和流水数据。
- BRAM：芯片内部存储。
- DSP：适合乘法、加法等运算的专用单元。
- 时序裕量：数据能否在要求的时钟截止前稳定到达，正值表示该项约束通过。

+0.007 ns 只有 7 ps，说明当前建立时序通过，但余量很小。它不是“还能随意把频率大幅提高”的证明。

也不能只凭 BRAM 使能优化就写出一个未经测量的功耗降低百分比。

### 14.5 验证为什么分很多层

| 层次 | 主要回答什么 |
| --- | --- |
| 数学、检测和接口单元测试 | 某个模块的边界和算法是否正确 |
| 完整核心仿真 | 模块连起来后，数据、窗口和结果能否一致 |
| 位精确 FFT 比较 | 固定位宽、缩放和舍入下的复数结果是否匹配参考 |
| 布局布线与时序检查 | 目标器件在目标频率下能否实现 |
| 实板数值矩阵 | 真板输出是否匹配指定参考和边界条件 |
| 动态切换和故障注入 | 更新数据、异常输入时是否保持正确提交 |
| 连续运行和计数守恒 | 较长测试内有没有丢样、丢记录或错误 |
| SD 自动启动、断电冷启动 | 不依赖临时 JTAG 下载时能否启动并复验 |
| 源码、镜像和散列绑定 | 测试结果能否追溯到对应版本和文件 |

项目已有归档包括：

- 完整核心 1048576 个复数 FFT 点的位精确比较。
- 79 项实板数值检查。
- 272 项宽带检查。
- 1000 次动态 Bank 切换及异常拒绝测试。
- 60 秒、300 秒连续运行。
- 独立的断电冷启动复验。
- 11 月新增演示输入和实板结果的离线数值复核。

这些结果有各自测试输入、运行条件和版本身份。通过若干已测条件，不等于证明任意输入、任意供电、无限运行时间都不会出现问题。

### 14.6 历史批次不能混为一次实验

| 归档 | 应怎样理解 |
| --- | --- |
| 10 月的正式报告补测 | PPT、报告中若干数值与截图的原始批次 |
| 10 月 13 日物理断电冷启动 | 用户实际断电重上电后，独立完成对应复验 |
| 11 月 2 日最终提交复现 | 新构建的 JTAG/RAM 实板验收，不代表该批又做过物理冷启动 |
| 11 月 3 日新增演示 | 增加了幅度阶跃、双音、扫频、OFDM 等展示与对应证据 |

这些测试可以共同支持项目，但不能把某批窗口数、另一批吞吐值和第三批冷启动动作拼成“同一次测试”。

### 14.7 当前仍存在的边界

- 输入是数字 IQ 文件回放，还没有外部 ADC 实时前端。
- 网口不持续供应 160 MSPS 的全新数据。
- 测长是活动包络，不是通信协议帧识别。
- 谱峰不是自动识别出的调制载频。
- 幅度是数字码值，没有电压或 dBm 标定。
- 所测低 SNR 条件存在漏检，不能靠提频就自动消除。
- 固定 16384 点下，频率格宽约 9.77 kHz，尚未做谱峰插值。
- BRAM 占用较高，时序裕量较小，增加功能前需要重新核算和验证。

| 环形缓冲 | 读写到末尾后绕回开头的一种队列结构 |
| BRAM | FPGA 片内专用存储 |
| CDC | 跨时钟域通信 |
| CRC | 检查数据内容完整性的校验码 |
| UDP | 本项目使用的网络数据报传输方式 |
| SHA-256 | 给文件生成内容指纹，用于核对文件是否一致 |
| Q16.16 | 一种固定小数表示，解码时整数除以 65536 |
| Build ID | 区分硬件构建版本的身份标识 |
| JTAG | 调试、配置或临时下载使用的接口 |
| BOOT.BIN | Zynq 启动时使用的一种打包镜像文件 |

Q16.16 能表示小数，不表示硬件测量本身一定具有 1/65536 码的实际准确度。表示格式、量化刻度和真实测量误差要分别理解。

SNR 以功率比定义：

| SNR | 信号功率与噪声功率的比例 |
| --- | --- |
| 0 dB | 大致相等 |
| 10 dB | 信号约为噪声的 10 倍 |
| 20 dB | 信号约为噪声的 100 倍 |

本项目含噪例子的 SNR 来自数字向量生成设定，不是本文又用射频仪器重新测得的结果。
