## 1. 目标与结论

依据 `D:\fft\赛道2_FPGA设计及应用赛题整理.md`，项目需在 FPGA 上完成数字基带信号的幅度、帧长度、频点、带宽分析，提供 RTL、前仿真和板级测试证据。

当前基线已达到题面明确列出的四项数值门槛。后续重点是完善帧长语义和误差验证、改善时序、整理可复现工程以及参赛证据。采用 AMD FFT IP、板内数字回放的事实应如实声明；题面未明确禁止这两项，也未要求外部 ADC。主办方如另有补充规则，应据其调整，不能把个人解释当作官方承诺。

本轮继续使用现有 Zybo、电脑、SD 卡、USB 和网线；维持 100 MSPS 输入、125 MHz FFT 核及 8192 点 FFT。125 MSPS 输入、换板、自主 FFT、射频接收、外部 ADC 不属于本轮实施范围。

### 2.1 实际数据路径

```mermaid
flowchart LR
    PC["电脑生成或选择 I16/Q16 文件"] --> PS["以太网上传 / ARM装载"]
    PS --> RAM["32768对 IQ 回放RAM"]
    RAM -->|"100 MSPS"| TIME["幅度与突发长度"]
    RAM --> FIFO["跨时钟FIFO"]
    FIFO --> FFT["矩形/Hann窗 + 8192点FFT"]
    FFT --> SPEC["功率谱 / 谱峰 / 99%占用带宽"]

    SPEC --> RECORD
    RECORD --> OUT["ARM发送 / 电脑显示与导出"]
```

电脑先上传有限长度波形，再由FPGA连续回放。最大32768对IQ对应327.68 µs；连续测试重复该段数字波形。100 MSPS不是电脑经千兆网口持续输送新数据的速度：16+16位格式需要400 MB/s原始带宽，超过1 Gbit/s链路。

## 5. T02/T03：帧长度完善

### 5.1 先定义测量对象

- **门限突发长度**：现有16点滑动能量、双门限和连续确认得到的区间。
- **零背景数字波形长度**：量化I/Q非零样本按最小连续零间隔分组后，首个非零到最后非零的下一点。
- **协议帧长度**：需要协议前导、帧同步和结构解释，本工程不宣称已实现。

例：`burst_fs4`真实非零长度24576点，原门限算法输出24591点，相差15点/150 ns。差值随幅度、门限、包络、噪声变化，不能对全部信号固定减15。QPSK生成器的卷积数组范围也不必等于量化后的非零范围。

### 5.2 推荐实施方式

保留默认门限模式，增加仅适用于数字零背景测试信号的可选模式：

1. 对有效样本计算 `p=I²+Q²`，`p>0`判为非零。
2. 空闲遇首个非零样本，记录start、能量、峰值。
3. 活动期间记录last_nonzero，累计能量和峰值；内部短零段计入区间长度。
4. 连续零样本达到gap_min，输出 `end=last_nonzero+1`、`length=end-start`。
5. 结尾确认零段不计入长度，RMS按真正输出区间重新计算。
6. `valid=0`不是零输入，不递增有效样本编号和零间隔计数。
7. 采集结束、最大长度强制分段、起点未确认需显式标志；不得将不完整观测段称为完整通信帧。
8. 噪声或直流偏置使背景不再精确为零时，使用门限模式并报告误差。

最大长度可小于零确认间隔。此时TIMEOUT记录为强制切分的观测段，不能当作独立完整帧；所有分段不得丢样或重复，能量/RMS必须与所报区间对应。

## 6. T04：频谱关键路径优化

现有关键路径为ROI范围判断、功率选择与峰值更新组合逻辑，125 MHz建立时间裕量仅0.109 ns。

本轮采用小范围调整：在ROI筛选后的功率、频点编号、有效、帧尾和溢出信息之间增加一致的流水寄存，切断长组合路径。吞吐仍为每周期一个FFT输出；不改变窗口、缩放、峰值相同时选择较低频点、双缓冲和99%功率分位算法。

新增一拍意味着该阶段约增加8 ns。此项首先追求时序裕量，不声称一定缩短总延迟。是否保留以布局布线实际结果为准。

验收：

1. 原位精确结果全部一致。
2. 单点ROI、ROI边缘、连续双bank、末频点、同峰、溢出与显示快照测试通过。
3. 布局布线setup/hold均非负、CDC Critical=0、无未约束内部端点。
4. 记录新旧时序、资源和实际分析/发布延迟；不得只报告有利数字。
5. 如新增局部路径时序恶化或结果不一致，回退该局部实现。若局部路径改善而全局瓶颈转移，应报告整体裕量变化、限定原时钟，并通过全链路板测后决定是否保留。

2026-09-19执行复核：原ROI/峰值最差路径0.109ns，本轮ROI输入端点1.261ns、峰值端点1.016ns；全局最差转为FFT IP内部高扇出布线，setup为0.030ns、hold为0.004ns。保留局部流水结构，整体时序余量下降如实记录，不能宣传全局提升或据此提频。

硬件当前在线也不能跳过构建关卡。JTAG装载只改变RAM中的运行版本；若未更新实体SD卡，断电后仍可能回到旧版，必须在状态报告中单独说明。

### 8.2 实板测试选取

- 原始8种向量×矩形/Hann窗全部有限采集。

## 11. T08～T10：后续性能探索

### 11.1 扩展信号验证（P1）

固定100MSPS，先扩展载频偏移、幅度、窗函数、噪声和ROI边界，再考虑更宽数字波形。候选60/70/80MHz只是生成目标，实际成绩使用完整8192点谱测得的99%占用带宽。

- 复基带频轴为[-50,+50)MHz，留保护带，不把整个频轴等同已验证信号带宽。
- RRC理想支撑带宽、符号率和99%占用带宽分别记录。
- 量化后检查峰均比和溢出，固定随机seed。
- 当前线性CDF算法不支持跨Nyquist边界的环绕最短带宽，不用这类输入虚增结果。
- 新增波形先有限核对，最宽稳定波形再做60秒连续验证。
- 窗函数、短突发、循环接缝和噪声的影响分别报告。

### 11.2 更低延迟（P2）

先分阶段记录首输入、FFT首/末输出、bank就绪、带宽扫描和结果发布时间。100MSPS收满8192点需要81.92µs，是完整窗口结果不可忽略的输入积累时间。

现有扫描每拍2点，扫描8192点约4096周期/32.768µs。4点并行扫描可作为实验，但会增加RAM组织、前缀累加和比较复杂度；不得将扫描理论减半直接说成系统延迟减半。每次只改变一项，保留资源/时序/延迟的完整对比。

### 11.3 125MSPS（P2，可失败的独立探索）

必须先统一真实采样时钟、频率换算、记录元数据和主机显示，不能只改软件显示值。

检查范围：`build_board.tcl`、`create_fft.tcl`、`iq_peripheral.sv`、`result_builder.sv`、固件、客户端、GUI、参考模型和全部验收脚本。原`390625/32`对应100MHz/8192，125MSPS下频点间隔变为15.258789kHz；若时间戳时钟也为125MHz，2ms对应250000周期。

125MSPS输入配125MHz核失去原有吞吐余量，需持续仿真确认FFT ready、FIFO占用和长期服务率；有限FIFO不能补偿平均吞吐不足。若考虑更高FFT时钟，先证明时序可收敛。完整重建IP/板级工程/XSA/软件/BOOT并重新板测后，才能将该档位写入成果。失败时继续使用已验证100MSPS版。
