# 使用与设计说明

## 1. 这个工程完成什么

工程将既有方案实现为 FPGA 逻辑、处理器软件和电脑端工具。信号由电脑生成或从现有 I/Q 文件读取，装入 FPGA 回放 RAM；开始采集后，FPGA 每 10 ns 处理一组 16 bit I、16 bit Q。

本文说明当前源码的使用方法与接口，包括硬件版本 `0x00010001` 的可选数字零背景检测。当前构建、实板验证和实体 SD 启动状态统一见 [验收状态](验收状态.md)。下面的操作步骤和预期数值不代表本轮实板验收已经完成。

每连续 8192 组样本形成一个频域窗口，得到：

1. 原始 I/Q 的包络峰值、窗口 RMS 和能量。
2. 8192 点复数 FFT 及功率谱。
3. 频谱最高点所在的频率。
4. 99% 占用带宽的低端、高端、宽度及带宽中心。
5. 窗口编号、样本位置、时间戳、处理延迟及异常标志。

另一路长度检测在原始样本上连续运行，可选择门限突发检测或数字零背景波形检测，输出区间起点、结束位置、长度、峰值和 RMS。检测区间可以跨越多个 FFT 窗口；两种方式均不识别通信协议帧头。

**当前输入来自电脑预先装载后的板上 RAM 回放，不包含 ADC 或射频接收。100 MSPS 指 FPGA 分析入口的数据速率，千兆网口不实时连续传入每秒一亿组新的 I/Q 数据。**

## 2. 现有设备与运行方式

### 2.1 最小 JTAG 验证

需要 Zybo Z7-20、电源和支持数据传输的 Micro-USB 线。电脑已安装 Vivado / Vitis 2026.1。将板卡 USB JTAG/UART 接口连接电脑，正常上电；JTAG 启动模式最便于调试。

这种方式由调试器初始化 Zynq、下载 PL 比特流、将测试数据写入回放 RAM，再启动有限长度采集。采集结束后读回结果。**实际采样过程由 FPGA 的 100 MHz 时钟驱动，不受 JTAG 写文件速度影响。**

### 2.2 连续以太网验证

在前述基础上增加一根网线，连接板卡 RJ45 和电脑千兆网口；电脑无网口时用 USB 千兆网卡。

固件默认板卡地址 `192.168.1.10/24`，UDP 端口 `5001`。电脑相应网卡设置一个不同的同网段地址，例如 `192.168.1.20/24`。这是板卡与电脑直连时的配置示例；不要与已有网络地址冲突。

本工程采用静态 IP。UART 为 115200、8N1，用来查看启动和网络状态；完整高速结果通过以太网传送。

## 3. 构建入口

### 已生成包的优先使用方法

构建与打包流程生成两种独立启动包，使用同一份 PL 电路；是否已完成本轮构建和验证，以相应报告和散列为准：

| 目录 | 用途 |
|---|---|
| `release/sd_card` | SD 自动测试：8 种输入 × 2 种窗，离线保存全部测量与快照 |
| `release/ethernet_sd_card` | 以太网交互：电脑装入任意合规 IQ 文件，有限或连续运行 |
| `artifacts` | bit、XSA、两种 ELF、FSBL、初始化脚本与两种 BOOT 镜像 |

对现有 32 GB SD 卡，使用已有 **FAT32 分区**，将选定目录的**内容**复制到根目录；不要将两套 `BOOT.BIN` 混在一起。这里是文件复制，不是磁盘镜像烧录。本工程不会格式化 SD 卡。板卡断电时插卡，按板上标识和对应修订手册选择 SD 启动，接通电源；UART 参数为 115200、8N1。

SD 自动测试模式的根目录应含 `BOOT.BIN` 和 `VECTORS` 文件夹，其中 `VECTORS` 有 `ZERO.BIN`、`POS25.BIN`、`NEG25.BIN`、`BURST.BIN`、`QPSK4.BIN`、`QPSK2.BIN`、`SHORT512.BIN`、`FULLNEG.BIN`。程序每次启动新建 `RUN0000`、`RUN0001` 等目录，不覆盖已有结果。

每个运行目录中，`C00`–`C07` 是矩形窗，`C08`–`C15` 是 Hann 窗。每个子目录保存 `FREQ.BIN`、`BURST.BIN`、`META.JSON`，以及成功抓到的 `SNAP.BIN`。SD 读写发生在有限采集之前和之后；实际 IQ 处理期间由 PL 回放 RAM 每拍供数，不依赖 SD 卡吞吐。

这套 SD 自动测试仍为默认 `threshold` 模式，共 16 组。新版 SD 固件显式写入 `mode=0`、`gap_min=32`，并在 `META.JSON` 记录硬件版本和采样率。`analyze_sd.py` 仅用于这套门限参考；它会拒绝把标为 `digital-zero` 的数据套入旧门限长度参考。新版数字零模式使用下面的网络采集和验收流程。

看到串口 `SD_CAPTURE_COMPLETE` 后，文件已关闭。关闭板卡电源，再取卡读回结果。假设读卡器盘符为 `E:`：

```powershell
python .\host\analyze_sd.py 'E:\RUN0000' --out .\captures\sd_run0000
python .\host\monitor.py
```

`analyze_sd.py` 将实测原始整数记录与 AMD 位精确参考逐项比较，输出 `board_validation.json`。该文件必须来自真实板卡结果；工程预备的仿真结果不能冒充板测数据。

电脑界面可以打开解码后的 `Cxx` 目录，或者直接打开 SD 上的 `Cxx`。选择正确的 IQ 输入文件再查看包络：包络是装载文件参考；频谱快照和测量数字来自 PL。以太网启动包支持界面中的开始采集与窗口边界停止按钮。界面主要数值约 10 Hz 刷新，频谱快照最高约 2 Hz；完整记录仍持续接收并保存。

`artifacts/BOOT.BIN` 默认等同于 SD 自动测试版本；`BOOT_sd.BIN` 与 `BOOT_udp.BIN` 是显式命名版本。此前仅用网络固件的操作方式对应 `BOOT_udp.BIN`。

所有命令在 `D:\fft\iq_analyzer` 执行。`scripts/run.ps1` 可用 `-VivadoRoot`、`-VitisRoot`、`-Python` 指定其他安装位置。

```powershell
Set-Location D:\fft\iq_analyzer
.\scripts\run.ps1 -Action All
```

主要阶段：

| 阶段 | 作用 |
|---|---|
| `Reference` | 生成 AMD 位精确 FFT 参考和算术边界测试数据 |
| `Sim` | 核心、总线、整数运算、队列、频率换算和电脑端回归 |
| `Hardware` | 创建 PS/PL 工程、综合、布局布线、时序检查、导出 bit/XSA |
| `Software` | 用 Vitis Python API 构建 UDP/SD 两种应用和 FSBL |
| `Package` | 校验硬件/软件/仿真结果，生成两种 BOOT.BIN、SD 目录、源码 ZIP 与散列清单 |

完整 FFT RTL 仿真使用厂商硬件模型，耗时可能较长。日志和报告保留在工程内；失败时应定位错误后重建，不能跳过检查后声称通过。

Vitis 2026.1 中旧 XSCT 建工程接口已停用，本工程使用 Python API。该安装版本的 lwIP 元数据将可替代的 MAC 依赖列为平铺列表，但依赖检查器按“全部都需要”处理。构建脚本在 `build/local_sw_repo` 建立局部副本，将依赖明确限定为本板的 GEM，并使用已存在的 Cortex-A9 SCU 定时器。补丁范围及来源保留在脚本中，不修改 AMD 安装目录。

## 4. 第一次上板：仅使用 JTAG

在 Vivado Hardware Manager 中连接本地硬件服务器，或者启动安装目录中的 `hw_server.bat`。确保能够枚举到 XC7Z020。

先运行正频率单音：

```powershell
& 'D:\VivadoMM\2026.1\Vitis\bin\xsdb.bat' `
  .\scripts\jtag_capture.tcl `
  'D:\fft\iq_analyzer\data\vectors\tone_pos_fs4.bin' `
  'D:\fft\iq_analyzer\captures\jtag_tone'

python .\host\iq_client.py decode `
  --freq .\captures\jtag_tone\frequency.bin `
  --burst .\captures\jtag_tone\burst.bin `
  --out .\captures\jtag_tone\decoded
```

JTAG 脚本重新配置 FPGA，使用复位后的 threshold 检测器与默认 Hann 窗；本脚本没有数字零模式选择项。应看到 4 条频域结果，峰频率约 +25 MHz，原始窗口峰值和 RMS 为 8192 码值。Hann 窗单音能量落在主频点及邻点，99% 带宽约 24.414 kHz；矩形窗相干单音的带宽则可能为 0，并带 `RESOLUTION_LIMITED` 标志。

继续依次运行 `tone_neg_fs4.bin`、`burst_fs4.bin`、`qpsk_sps4.bin`、`qpsk_sps2.bin`、`short512_boundary.bin`、`negative_fullscale_dc.bin`、`zero.bin`。每次保存在独立目录，保留 `jtag_capture.txt` 作为实际板测来源。

脚本只向 RAM 下载，不烧写 QSPI 或修改 SD 卡。

## 5. 以太网采集

### 5.1 下载固件

需要先完成当前源码的 `scripts/run.ps1 -Action All`，再通过下面的入口下载匹配的 bitstream、ARM 程序并记录部署散列。此操作仅装载 FPGA 和 DDR，不更新实体 SD 卡。

```powershell
python .\scripts\deploy_board.py --board 192.168.1.10
```

该入口调用 `program_board.tcl`，检查新模式的版本/能力、STOPPED 状态和错误计数，写入 `reports/current_deployment.json`。Vitis 不在默认路径时，用 `--xsdb '实际路径\xsdb.bat'` 指定。等待 UART 显示网卡初始化和 IP 信息。

也可以使用经过当前构建流程生成的 `release/ethernet_sd_card/BOOT.BIN`，复制到 FAT32 SD 卡根目录，按板卡手册设置 SD 启动后重新上电。必须单独记录该卡的镜像散列和上电版本；JTAG 验证通过不等于这张卡已更新。下述自动网络验收入口当前要求存在匹配的 JTAG 部署记录，不能仅用一次 SD 启动替代该证据链。

### 5.2 单次采集

```powershell
python .\host\iq_client.py capture --board 192.168.1.10 `
  --vector 'D:\fft\iq_analyzer\data\vectors\qpsk_sps4.bin' `
  --window hann --detector threshold --out .\captures\qpsk4
```

省略 `--detector` 时默认使用 `threshold`。采集前先停止已有采集，选择一个新的输出目录。新版数字零模式的单次演示使用：

```powershell
python .\host\iq_client.py capture --board 192.168.1.10 `
  --vector .\data\vectors\burst_fs4.bin --window hann `
  --detector digital-zero --gap-min 32 --out .\captures\digital_zero_finite
```

主机要求硬件版本至少为 `0x00010001`，并且能力寄存器 bit0 为 1；不支持时明确报错，必须更新匹配的硬件与网络固件。主机读回模式和间隔配置后才开始采集。该向量在数字零模式下的参考区间为 `[2048, 26624)`，长度应为 **24,576 点，即 245.76 µs**；这是预期值，需核对本次实际记录。

程序装入数据、提交配置、启动采集、接收结果，并生成：

- `frequency.bin` / `burst.bin`：原始记录，可重新解码。
- `frequency.json` / `burst.json`：便于程序处理的测量值。
- CSV：便于表格查看。
- `capture.json`：输入文件散列、硬件版本/能力、`detector_mode`、`gap_min`、采样率、采样数、硬件错误、队列丢弃、缺失记录和参考核验状态。
- `结果说明.md`：便于阅读的频率、带宽、幅度摘要。

### 5.3 连续运行

```powershell
python .\host\iq_client.py capture --board 192.168.1.10 `
  --vector 'D:\fft\iq_analyzer\data\vectors\qpsk_sps2.bin' `
  --window hann --detector digital-zero --gap-min 32 `
  --cyclic --seconds 10 --out .\captures\continuous10s
```

到时后，程序请求停止。硬件在完整窗口边界停下，并等待最后结果发布完成。UDP 不是可靠传输，电脑端会利用包序号、硬件完成数和队列计数检查结果完整性；出现丢失时保留数据并报告失败。

循环模式反复回放同一段装载数据，零间隔与波形可能跨越 RAM 回放边界，检测器不会在每次回放折返时重置。停源保证 FFT 窗口完整，但最后一段波形可能仍未确认结束，需同时查看长度记录的 flags。

```powershell
python .\host\iq_client.py stop --board 192.168.1.10
# 必要时显式中止；中止会丢弃当前流水线和未读队列。
python .\host\iq_client.py stop --board 192.168.1.10 --abort
```

一次只运行一个采集端。GUI 采集中应点“窗口边界停止”；UDP 固件在运行时只接受当前采集端的 IP/端口，另开一个 CLI 进程不保证能接管它的活动会话。

## 6. 结果该怎样理解

### 幅度不是电压

输入是 int16 的数字码值。幅度定义为 `sqrt(I²+Q²)`；输出采用无符号 UQ16.16，即记录整数除以 65536。

FFT 加窗不改变独立时域测量的原始幅度。窗口 RMS 对整个 8192 点求均方根，所以一帧内有一半零样本时，窗口 RMS 会降低。突发 RMS 按检测到的突发区间计算。

I 和 Q 都等于 -32768 时，复数幅度约 46340.95，不能用有符号 16 位幅度保存。本工程显式处理了这一边界。

### 峰频率和载波频率不同

单音最高点通常就是单音频率。QPSK 等宽带随机调制信号的最高谱线可能偏离载波中心，因此同时输出带宽中心。不要强求 QPSK 的最高点固定等于设置的 8 MHz 载波偏移。

### 带宽定义

将频谱按 -Fs/2 到 +Fs/2 排列，在设置的 ROI 内累积线性功率。低端取累积功率首次达到 `ceil(T/200)` 的点，高端取首次达到 `T-floor(T/200)` 的点。带宽使用两端频点中心之差。

这里 `Fs=100 MHz`、`N=8192`，频点间隔为 **12,207.03125 Hz**。单音宽度为 0 代表无法在该频率分辨率下分辨更窄的宽度，不代表信号在物理上没有带宽。

ROI 边界被触及会置 `EDGE_RISK`。噪声、窗函数、短突发与窗口边缘位置都会影响测量；这些影响不能用缩窄 ROI 隐藏。快照是每 8 点取最大值的 1024 点显示数据，正式带宽仍由完整 8192 点功率计算。

### 两种长度定义

所有长度区间采用 `[start, end)`，长度为 `end-start`，单位是一对 I/Q。两种模式共用 64 字节 burst 记录，但测量定义不同，比较参考结果时必须匹配模式。

| 模式 | 规则 | 适用含义 |
|---|---|---|
| `threshold`，默认 | 16 点滑动功率和，双门限与连续确认；默认 Ton=1,048,576、Toff=262,144、Kon=8、Koff=32 | 超过门限且通过确认的能量突发 |
| `digital-zero` | `I!=0` 或 `Q!=0` 判为非零；连续 `gap_min` 个 `I=Q=0` 确认段间空闲 | 有明确全零背景的量化波形区间 |

`burst_fs4` 的量化非零区间为 `[2048,26624)`。默认门限模式的参考长度为 **24,591 点**，多出的 15 点来自滑动和尾部；数字零模式在默认间隔 32、完整观测条件下的参考长度为 **24,576 点**。二者不能用同一套 golden 长度判定。

数字零模式把短于 `gap_min` 的内部零段保留在同一波形中，并计入长度与 RMS 分母。确认结束后，终点回指最后一个非零样本的下一个位置，后续用于确认的全零样本不计入完整波形长度。这里的“零”是量化后的 `I=Q=0`，不推断模拟噪声底，也不恢复量化前已经消失的小幅尾部。

如果采集开始时，波形之前观察到的连续零样本少于 `gap_min`，置 `START_UNCONFIRMED`。采集停止前尚未等到足够尾零时，置 `CAPTURE_TRUNCATED`；此时终点取已观测样本末尾，尚未确认的尾零仍属于记录区间。达到 `max_burst` 时强制分段并置 `DETECTOR_TIMEOUT`，后续分段也会标记起点未确认。带这些标志的区间不能作为“起止均确认的完整波形长度”。

这两种功能都不做协议同步、帧头识别或载荷解码。报告中应使用“门限突发长度”或“数字零背景波形长度”，不能据此称为已识别通信协议帧。

### 标志与时间换算

burst 记录的 `word[1]`（从0计数，字节偏移4）为 flags，新增位不改变原有 64 字节长度：

| bit | 标志 | 含义 |
|---|---|---|
| 8 | `CAPTURE_TRUNCATED` | 停止前未确认结束，区间在采集末尾截断 |
| 10 | `DETECTOR_TIMEOUT` | 到达最大允许长度，输出观测分段 |
| 12 | `DIGITAL_ZERO` | 此记录来自数字零背景模式；未置位时为门限模式 |
| 13 | `START_UNCONFIRMED` | 前导零不足，或属于长度上限后的续段，不能声称真实帧头已确认 |

分析延迟、发布时间和波形持续时间使用相应记录/元数据中的非零 `sample_rate_hz` 换算：`微秒=周期或样本数×1,000,000/sample_rate_hz`。2 ms 验收应比较换算后的时间。当前硬件仍固定 100 MSPS；软件按记录采样率换算不代表已经实现 125 MSPS。

## 7. 电路结构

```mermaid
flowchart LR
  PC[电脑: IQ 文件与结果保存] <-->|以太网| PS[Cortex-A9 / lwIP]
  PS <-->|AXI Lite 100 MHz| MMIO[控制、回放 RAM、结果队列]
  MMIO -->|16+16 bit / 100 MSPS| TIME[原始功率 / 幅度 / 突发检测]
  MMIO --> FIFO[4096 点异步 FIFO]
  FIFO --> WIN[125 MHz / 矩形或 Hann 窗]
  WIN --> FFT[AMD 8192 点 FFT]
  FFT --> SPEC[功率谱双缓冲]
  SPEC --> BW[双点扫描 / 99% 带宽]
  BW --> CDC[频域结果跨时钟 FIFO]
  CDC --> JOIN[配对 / 整数开方 / 记录组装]
  TIME --> JOIN
  JOIN --> MMIO
```

PS FCLK0 产生 100 MHz，FCLK1 产生 125 MHz。这里使用 PS 提供的两个时钟，替代方案草稿中的 Clocking Wizard。跨域样本和频域结果使用 XPM 异步 FIFO；静态配置在启动前稳定并同步；快照窗口编号通过握手跨域。

FFT 参数：8192 点、单通道、24 位定点、18 位旋转因子、流水流式结构、收敛舍入、位逆序输出、带真实频点下标、非实时 AXI Stream 模式。总缩放为 14 位，每次复位后发送配置 `0x3557`。位逆序输出通过下标写入有符号频率顺序的功率 RAM。

Hann 系数使用 U18.17，原始 int16 与系数乘积除以 512 后按偶数舍入为 24 位。矩形窗等效为原始样本左移 8 位。

频域功率使用 48 位，累加使用 64 位。两个功率缓冲区交替写入与扫描，每拍扫描两个频点。结果跨回 100 MHz 域，与同窗口的原始能量和峰值配对。

窗口编号从每次采集的 0 开始。固定配置、连续采样及固定 8192 点长度允许采用顺序上下文队列配对；队列溢出、输入损失或配对错误会记录异常，不能将这些记录当正常结果使用。

## 8. 地址与控制

AXI 基地址：`0x40000000`，大小 256 KiB。以下为偏移。

| 地址段 | 内容 |
|---|---|
| `0x00000–0x00FFF` | 控制与状态 |
| `0x10000–0x2FFFF` | 32768 × 32 位 I/Q 回放 RAM |
| `0x30000–0x37FFF` | 256 条 × 128 字节频域记录 |
| `0x38000–0x39FFF` | 128 条 × 64 字节突发记录 |
| `0x3A000–0x3BFFF` | 1024 × 64 位显示快照 |

| 偏移 | 内容 |
|---|---|
| `0x000` / `0x004` | MAGIC=`0x49514131` / VERSION；本轮接口版本 `0x00010001` |
| `0x008` | 状态：低 3 位运行状态；bit8 活动；bit9 核就绪；bit10 快照有效；bit11 配置待提交 |
| `0x00C` | W1 命令：bit0 START，bit1 STOP，bit2 ABORT |
| `0x010/014/018` | 100 MHz / 125 MHz / 8192 |
| `0x01C/020/024` | 回放长度 / 起始地址（样本数）/ 单次0或循环1 |
| `0x028/02C/030` | 窗0矩形1Hann / ROI低 / ROI高，ROI频点含端点 |
| `0x034/038` | Ton 的低32/高4位 |
| `0x03C/040` | Toff 的低32/高4位 |
| `0x044/048/04C` | Kon / Koff / 最大突发样本数 |
| `0x050/054` | 频域 producer / consumer |
| `0x058/05C` | 突发 producer / consumer |
| `0x060/064` | 错误状态 / 主机侧错误 W1C |
| `0x068/06C/070` | epoch / config_id / 配置提交，写1 |
| `0x078/07C/080` | 快照申请bit0、释放bit1 / valid与pending / window_id |
| `0x084` | `DETECTOR_MODE`：0=threshold，1=digital-zero；复位默认0 |
| `0x088` | `GAP_MIN`：数字零间隔确认点数，1–65535；复位默认32 |
| `0x08C` | 只读 `CAPABILITIES`：bit0=支持数字零模式；当前值1 |
| `0x100` | 写任意值锁存统计快照 |
| `0x110/114` | 64位源时钟计数快照 |
| `0x118/11C` | 64位样本计数快照 |
| `0x120/124/128` | 完成窗口数 / 最大分析延迟 / 最大发布延迟（100 MHz周期） |
| `0x12C/130` | 频域 / 突发队列丢弃数 |

运行状态：STOPPED=0、RESET_CORE=1、WAIT_CORE=2、RUNNING=3、DRAINING=4。配置与回放内容只在 STOPPED 修改。修改配置后写 COMMIT，通过合法性检查后才能 START。每次 START 清空采集内部状态和队列，因此启动前必须已经消费上一轮结果；ABORT 是显式丢弃操作。

两种检测模式均要求原有门限与确认参数合法：Ton>Toff，Kon/Koff 在 1–65535 范围。门限模式要求 `max_burst>=Kon`；数字零模式允许 `max_burst>=1`；共同上限为 1,048,576 点。`GAP_MIN` 以完整 32 位寄存器保存并验证范围，不能把超范围配置通过截位变成合法值。模式和 gap 与其他配置一同提交，只在停止状态下修改。

producer 和 consumer 为单调 32 位计数器。读取不会自动释放记录；软件读完后写 consumer。队列满时丢弃新记录并计数，不覆盖尚未读取的记录。结果内容写完后才更新 producer。

运行中的改写、非法地址或非法配置返回 AXI `SLVERR`。以太网固件在访问总线前检查参数，避免把无效命令直接发给硬件。

### UDP 配置兼容

UDP CONFIG 命令类型仍为 4。原 13 个 payload word 按顺序为：`length, cyclic, window, roi_low, roi_high, ton_low, ton_high, toff_low, toff_high, kon, koff, max_burst, replay_start`。当前网络固件要求 `replay_start=0`。

新版支持在末尾追加 `mode, gap_min`，形成 15 word 配置；加上 16 字节协议头，请求共 76 字节。旧 13 word 请求共 68 字节仍可用，新固件收到它时显式恢复 `mode=0, gap_min=32`，避免继承上一轮数字零配置。

主机先读 VERSION 和 CAPABILITIES。旧版 `0x00010000` 继续使用 13 word 门限配置；选择数字零模式则报不支持，不会偷偷回退。新版发送 15 word，并读回 `0x084/0x088` 确认。新硬件搭配旧 UDP 固件会被识别为版本/能力读取不一致，应重新部署匹配的 bitstream 和 ELF/BOOT。

## 9. 测试与验收顺序

1. 运行数值回归，检查 `core_validation.json` 的 PASS 和记录数量。
2. 检查 `build/logs/` 下的模块、核心、AXI、数字帧长与频谱边界日志，必须有对应 PASS，不能有 Fatal。
3. 检查最新布局布线的 setup/hold 裕量、未约束端点、DRC 和 CDC。
4. JTAG 运行所有标准向量，保存实际板测文件，与参考数据比较。
5. 以太网有限采集检查记录格式与完整性。
6. 连续运行至少 10 秒，再延长到 60 秒，检查所有硬件错误和丢弃计数为 0。
7. 主动让电脑停止接收，确认硬件统计能暴露结果丢失；恢复后不能将不完整结果报告成完整采集。
8. 保存比特流、ELF、工具版本、源码散列、时序和资源报告，整理比赛材料。

2026-09-17 基线的 SD、以太网10/60秒、突发压力和故障恢复证据保存在 `reports/baseline_20260917/`。当前优化版本的验证状态统一见 [验收状态](验收状态.md)，不能将历史板测自动套用到新版本。

## 12. 实现边界与后续优化

- 当前冻结为 100 MSPS、125 MHz FFT 核、固定 8192 点；125 MSPS 档需要另一轮实现与验收，不能只改软件中显示的采样率。
- 回放长度限 8192/16384/24576/32768 个 IQ 对。短突发包含在正常的零值样本窗口中，不把整个回放截成不足 8192 点。
- 方案中 64 槽随机访问上下文改为 16 槽顺序队列；通过编号核对配对，并对溢出置错。窗口无重叠、配置仅停止时修改，适合顺序配对。
- 结果队列为 256 条频域 / 128 条突发；满时丢弃新记录并计数。2026-09-17 基线验证过 60 秒连续采集及 20 秒、6103.516 次/秒突发压力；本轮需重新关联硬件版本验证。断网导致丢失时整轮判为不完整，恢复后重新采集。
- 收到异常后请求在窗口边界停源，结果携带或通过全局错误状态暴露失效。ABORT 用于明确丢弃在途数据。
- 频谱快照只用于显示；带宽用完整功率谱计算。缺少完整参考频谱时不根据显示快照重算后替代硬件带宽。
- 基线中的 SD 卡槽、FAT 文件读写、DDR 初始化和千兆 PHY 有实板证据。当前源码、JTAG 运行版本与实体 SD 上的 BOOT 必须分别核对，不能从基线报告推断新启动包已上电通过。
- 当前 JTAG 与网络文件装载均为内部数字回放，不包含外部 ADC 接口、射频前端或模拟量标定。
