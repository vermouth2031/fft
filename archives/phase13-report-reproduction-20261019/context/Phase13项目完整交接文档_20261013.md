## 1. 交接结论与快速定位

## 3. 赛题五项指标及其准确含义

赛题为“无线通信系统数字基带信号频谱分析电路设计”，要求实现幅度、帧长度、频点、带宽测量，以及 RTL 前仿真、板级测试和性能优化。原始整理见 [赛题要求](赛道2_FPGA设计及应用赛题整理.md)。

### 3.1 五项指标对照

| 序号 | 赛题指标 | 赛题要求 | 当前已验证结果 | 说明 |
|---|---|---|---|---|
| 1 | 数字基带 IQ 信号位宽 | ≥12 bit | **I16 / Q16** | I、Q 分别为 16 bit，一对复数样本共 32 bit；比最低要求各多 4 bit |
| 2 | IQ 信号数据速率 | ≥100 MSPS，越高越好 | **板内 160 MSPS** | 每秒消耗 1.6 亿对 IQ；相对 100 MSPS 高 60%；口径为 FPGA 回放输入通路 |
| 3 | FFT 点数 | ≥8192 点 | **16384 点** | 是最低要求的 2 倍 |
| 4 | 从接收 IQ 到得到频域信息的分析时间 | ≤2 ms，越低越好 | **最大 219.775 µs**；结果入环最大 **219.993750 µs** | 分别约 0.219775 / 0.219994 ms；均低于 2 ms；不含电脑上传和显示延迟 |
| 5 | 数字 IQ 信号带宽 | 单位 MHz，未给数值下限；越高越好 | **主组 99% 占用带宽 158.154297～158.593750 MHz** | 272 项宽带矩阵通过；300 秒连续 OFDM 组为 158.095703～158.554688 MHz |

前四项在上述项目口径下满足数值门槛；第五项给出已测带宽结果。原赛题没有规定第五项必须采用“99% 占用带宽”算法，也没有定义具体容差。正式答辩应说明本项目的带宽和输入速率口径，最终评分由赛方认定。

本文约158MHz的“主组带宽”专指 `primary` 组中的**满带子集**。272项矩阵还包含较窄带、频移和幅度变化用例，不是每一个用例都应达到158MHz。

### 3.2 160 MSPS 与网络上传的区别

一个复数 IQ 样本由 I16 和 Q16 组成，合计 4 字节。若要从外部持续送入 160 MSPS 的全新样本，仅净载荷就需要：

```text
160,000,000 对/秒 × 32 bit/对 = 5.12 Gbit/s = 640 MB/s
```

当前系统先上传一块 IQ 到 DDR/非活动 Bank，再让 FPGA 高速读取活动 Bank。新数据未准备好时，活动 Bank 可以重复回放。处理器和网口填充数据的速度与 FPGA 消耗 Bank 的速度是两个独立指标。

| 测量项目 | 当前数据 | 统计范围 |
|---|---:|---|
| FPGA 活动 Bank 消耗速率 | 160 MSPS | 内部回放通路 |
| RAM 1000 次 DMA 测试平均有效上传速率 | 22.126058 Mbit/s | 包含 UDP 有效载荷传输、DMA 提交和激活等待 |
| 冷启动 300 秒组平均有效上传速率 | 28.284526 Mbit/s | 同一测试程序定义，不同数据/调度条件的一次结果 |
| RAM 1000 次组每块平均 / 最大上传时间 | 47.391 / 63.000 ms | 每块 32768 对 IQ，即 131072 字节 |

这些有效上传数值不是千兆以太网物理链路的极限，也不能据此宣称已完成持续 160 MSPS 全新数据输入。

### 3.3 FFT 频率与时间尺度

| 派生指标 | 公式 | 当前值 |
|---|---|---:|
| 样本/源时钟周期 | 1 / 160 MHz | 6.25 ns |
| FFT 一窗采集跨度 | 16384 / 160 MSPS | 102.4 µs |
| 单个 32768 样本 Bank 的回放跨度 | 32768 / 160 MSPS | 204.8 µs |
| FFT 频率格宽 | 160 MHz / 16384 | 9765.625 Hz = 9.765625 kHz |
| 不重叠窗口的标称输入窗率 | 160 MSPS / 16384 | 9765.625 窗/秒 |
| 复数基带理论频域范围 | [−Fs/2, +Fs/2) | [−80, +80) MHz，总宽160MHz；最后一个离散格为+79.990234375MHz |
| 最大分析延迟对应计数 | 219.775 µs × 160 MHz | 35164 个源时钟周期 |
| 最大入环延迟对应计数 | 219.993750 µs × 160 MHz | 35199 个源时钟周期 |

“160 MHz 总频域跨度”和“约158 MHz 实测99%占用带宽”不是同一个数：前者由采样率决定，后者根据具体信号功率分布计算。频率格宽也不等于所有信号都能保证的绝对频率误差或双音可分辨间距。

分析延迟从 **板内 source/core 对该窗口标记首个有效样本的时间戳** 起算，到 `result_builder` 发布分析结果；入环延迟终点是结果进入主机可读取的环形缓冲区。它们都不是从电脑点击“开始”或发送首个 UDP 包开始计时。

单窗端到端延迟大于 102.4 µs，但流水线允许多个窗口处于不同处理阶段；不能简单用 `1 / 219.775 µs` 当作系统稳定吞吐窗率。

## 4. 测量功能、数值精度与算法边界

### 4.1 已实现功能

| 类别 | 已实现内容 | 使用边界 |
|---|---|---|
| 幅度 | 时域峰值、均方根 RMS、能量相关统计 | 数字码值；未标定成模拟电压、dBm 或射频功率 |
| 帧长度 | 突发起止、样本长度、相关标志；数字零检测和门限检测 | 依赖检测模式、最小间隔、长度上限及信噪比 |
| 频率 | FFT 功率谱峰值频点、频谱统计信息 | 受窗函数、格宽、频点偏移与短突发位置影响 |
| 带宽 | 两端各排除0.5%功率的99%占用带宽 | 当前不做谱线插值；不能等同任意调制的符号率或模拟−3 dB带宽 |
| 窗函数 | 矩形窗、Hann 窗 | 两者的泄漏、幅度与边界表现不同 |
| 信号 | 单音、双音、chirp、QPSK、OFDM、噪声、自定义 IQ | 各测试集覆盖范围见第8节，不表示所有通信制式都已验收 |
| 运行方式 | 有限长度采集、双 Bank 持续回放及动态数据切换 | 活动 Bank 重复使用不等于持续新数据输入 |
| 结果查看 | Python 命令行、上位机 GUI、频谱快照、频域及突发记录 | GUI刷新不是硬件分析时延 |
| 数据完整性 | 包/块 CRC、DMA 校验、记录序号、错误计数、样本守恒 | 故障拒绝与正常无错误要分别统计 |

FFT 数据通路使用 24 bit 数据、18 bit 旋转因子；I/Q 输入仍各16 bit。FFT 采用定点缩放及收敛舍入，功率谱为48 bit，总功率统计为64 bit。不能把内部24 bit运算写成外部输入24 bit。

当前“帧长度”测量的是突发信号包络，不识别通信协议的帧头、帧尾或协议字段。“频点”主要指最高谱线位置；对于宽带调制信号，该位置不一定等于载频。系统另外输出带宽中心等频谱信息，解释时应区分这些字段。

### 4.2 “完全一致”与“测得正确”的区别

完整核心仿真逐点核对 **1,048,576 个复数 FFT 输出**，以 AMD FFT bit-accurate C model 和独立整数时域/突发参考为基准。真板79项矩阵每轮核对80,896个快照值及频域/突发字段。

这证明当前硬件实现与规定的定点算法及测试参考一致。若算法在低幅度、噪声、窗边缘等场景本身产生偏差，硬件一致性检查仍可能通过。因此以下两类结论必须分开：

- **实现一致性：**硬件有没有按设计正确执行、数据有没有损坏、输出是否逐项匹配参考。
- **测量适用性：**该检测/估计方法对给定真实信号是否准确，是否有漏检、合并、分段或峰频偏移。

### 4.3 必须交接的当前边界实例

| 场景 | 当前观察 | 如何理解 |
|---|---|---|
| 0 dB 噪声组 | 3 个固定种子共6个真值突发，当前全部漏检 | 不能宣称已解决低信噪比帧检测 |
| 10 / 20 dB 对照组 | 各6个真值突发均检出，无误报 | 仅适用于这些固定种子和配置 |
| `boundary_16384_threshold_hann` | 40 MHz 真值的一条峰频输出为39.873047 MHz，偏差−126.953 kHz | 短/边缘突发乘Hann窗后的频谱变化；约13个当前FFT格 |
| `digital_gap_31_rect/hann`，`gap_min=32` | 两个相邻突发按配置合并；相对单独帧真值的最大长度差543样本，即3.39375 µs | 是间隔规则的预期行为，不能写成所有帧长度零误差 |
| 定点低幅信号 | 输入存在不代表经过窗和定点FFT后一定得到可用峰值 | 要结合幅度、门限与当前用例判断 |
| 超长帧/窗口边界 | 可能产生按上限分段、边界截断与相应标志 | 应核对记录标志和区间，而不是只看一个长度数字 |

整个79项压力矩阵的检测评估包含92个真值突发、88条检测区间：72个一对一匹配（其中70个为正常匹配）、20个未一对一匹配真值、误报0、2个合并检测、4个被拆分真值，以及16个未匹配但与真值重叠的检测区间。各类别的计数并非简单互斥可相加，且混合了人为低幅、噪声、间隔合并和长度分段压力用例，**不能把它直接作为常规通信信号的通用检测成功率**。

详细误差分组和宽带独立精度数据见本文附表及 [当前数值矩阵](fft_phase13_structure_opt/reports/phase13_cold_boot_20261013/finite/validation.json)、[宽带矩阵](fft_phase13_structure_opt/reports/phase13_wideband_trial09_20261012/validation.json)。

## 6. 系统架构、存储容量与数据格式

### 6.1 数据通路

```text
电脑：生成/选择 I16、Q16 → Python客户端或GUI
           │ UDP，通过以太网
           ▼
Zynq PS：Cortex-A9裸机固件 + lwIP → DDR块缓冲 / CRC校验
           │ AXI DMA，把完整新块搬到非活动Bank
           ▼
FPGA：Bank0 ↔ Bank1，完整FFT窗口边界切换
           │ 160 MSPS 回放
           ├──────────────→ 时域幅度 / 突发 / 帧长检测
           ▼
      输入FIFO → 窗函数 → 16384点FFT → 功率谱 / 八路谱扫描
                                                │
                                                ▼
                                  频域结果构建与结果环形队列
                                                │
                          PS通过网口返回记录和快照 → 电脑解码显示
```

PS负责网络、管理和搬运，PL负责高吞吐样本处理。双Bank结构使一块被分析时另一块可以装入新数据；只有数据完整、校验成功并满足切换条件，才将新Bank设为可用并在窗口边界切换。

### 6.2 容量与格式

| 对象 | 当前配置 | 换算/含义 |
|---|---:|---|
| 每个回放 Bank | 32768 对复数 IQ | 131072字节 = 128 KiB |
| 两个回放 Bank 合计 | 65536 对 IQ | 256 KiB有效IQ存储 |
| 常用单次上传块 | 16384 或 32768 对 | 64 KiB或128 KiB，必须适配当前FFT长度 |
| 输入 FIFO | 4096 个样本 | 保留BRAM实现 |
| 频域记录环 | 128 条 | 每条128字节，合计16 KiB有效记录容量 |
| 突发记录环 | 128 条 | 每条64字节，合计8 KiB有效记录容量 |
| 快照 | 1024 点 | 每16个FFT bin取组内最大功率，不是平均/求和；不可当完整16384点逐点频谱 |
| 频谱扫描 | 8路 | 每拍处理8个bin的并行扫描结构 |

二进制IQ文件按小端交错存储：`I0(int16), Q0(int16), I1(int16), Q1(int16), ...`。一个样本就是一对I/Q，不能把160MSPS再误乘2写成320MSPS复数采样率。输入有符号码范围为−32768～32767；部分测试限制峰码不超过32767以避免削顶。

`data/replay_vectors` 是直接回放使用的数据；`data/vectors` 中有供多窗核心回归使用的65536样本数据，不能不加检查直接当作一个物理Bank上传。部分旧CLI仍显示8192/24576候选长度，但当前16K版本应使用16384或32768。

### 7.2 具体电路调整

1. **DMA末尾提交流水化。**将末字节CRC、合法性判断、Bank路由和提交拆开；由 `iq_dma_commit.sv` 处理四阶段事务。末尾提交增加3个时钟，DMA在提交结束前保持忙，防止Bank尚未完成就被当成可用。
2. **Bank元数据统一管理。**`iq_bank_metadata.sv` 统一更新长度、block ID、CRC与ready状态，避免同一状态由多处组合条件竞争写入。取消/错误路径不产生成功提交。
3. **缩短控制路径。**寄存地址预解码、局部配置副本及ACK数据；用分段比较和已保存页码替代关键路径上的宽减法/页加一。
4. **ACK校验与执行分两步。**校验结果在明确时刻固定，合法ACK再原子更新消费者计数及下一页。ACK响应增加一个160MHz时钟，即6.25ns；采样与FFT流水线不增加相应一级。
5. **频率换算分解常数乘法。**将160000000拆成 `78125 × 2^11`，先完成较小乘积并寄存，再恢复缩放；运算安排在已有处理阶段内，DSP保持49。
6. **突发/长度条件提前计算。**把可以预测的下一拍判断寄存，保持既有事件时刻和计数语义，并用边界回归核对。
7. **回放BRAM按需使能。**只有实际访问时打开主机/回放端口，活动Bank的数据返回与延迟Bank选择对齐。最终网表64个回放RAMB36、128个A/B端口使能均为动态逻辑，常高端口为0。

第7项证明“使能优化确实映射到最终BRAM硬件”，不等于已测出某个百分比的总功耗下降。当前缺少足以独立量化该收益的电功率实验。

### 8.2 数值和宽带矩阵

每次79项数值矩阵包括幅度、边界、间隔、整数音、调制、噪声、双音和宽带等类别，合计158条频域记录、88条突发记录、80896个快照值。RAM阶段、SD复位阶段和真实断电阶段分别执行并分别保留记录。

272项宽带矩阵使用OFDM、独立种子、多个幅度与窗配置，项目准入阈值为边缘误差不超过2格、带宽误差不超过4格、分析时间不高于Phase12基线，主组最低目标158MHz。最终独立精度失败列表为空，主组带宽达到158.154297～158.593750MHz。

部分组件/接口回归的可量化覆盖还包括：DMA提交64次事务及3个取消阶段、数学范围10220组向量、ACK区间65536组、无符号分段比较65536组、ACK真实事务16次、容量页元数据逐周期检查322423次、回放逐样本计分245760个样本及1次实际Bank边界切换。它们用于覆盖原子更新、32位回绕、字节选通、复位/取消等普通波形测量难以发现的控制边界。

## 9. 供电、意外重启与剩余问题

### 9.1 已知事实

用户当前只有USB供电。Trial05在DMA连续测试中两次回到SD里的Phase12，用户确认未手动拔插、复位或操作电源。CPU复位标记消失、复位状态包含POR迹象，说明不是一次正常完成的候选验收。

同板、同USB条件下Phase12对照完成1000次DMA切换。最终Trial09采用BRAM按需使能以及进一步控制路径调整后，1000次、60/300秒、SD复位和真实断电后的300秒均通过，未复现同类重启。

### 9.2 能下的结论与不能下的结论

| 可以记录 | 尚不能认定 |
|---|---|
| Trial09在归档测试范围内通过 | 任意USB口、任意线材、任意环境长期运行都不会重启 |
| BRAM两端原生使能已在最终网表落实 | 总功耗已经下降某个确定百分比 |
| 复位类型及对照测试为排查提供证据 | USB压降已经被仪器捕获并证明是唯一根因 |
| 板载XADC记录覆盖相关DMA测试 | 约0.2秒的平均采样能够排除微秒/毫秒瞬态扰动 |

目前没有经过可靠电压/电流标定和受控变量实验的整机瓦数、每次FFT能耗或温升保证值。后续如需继续解决电气根因，应保留故障日志、做可控供电对照并增加足够时间分辨率的观测；本交接不把这些未完成工作当成已实现指标。

### 9.3 其他主要限制

- BRAM占用91.43%，再增FFT点数或缓存须重新规划存储，不能仅改参数。
- 建立余量仅7ps，再提频应重新设计和完整验证。
- 提高Fs而保持16384点，频率格宽变大；宽带提升与Hz分辨率之间存在取舍。
- 0dB噪声、低幅度、Hann边缘突发、合并/分段帧仍有第4节列出的边界。
- 当前不具备持续160MSPS全新网口数据输入，也没有外部ADC输入链路。
- 已完成的是有限时长、指定板卡和供电条件的测试，不是多年可靠性或所有环境认证。

### 16.2 常用术语

| 名称 | 本项目中的含义 |
|---|---|
| IQ | 一对表示复数信号的数字，I为实部、Q为虚部 |
| MSPS | 每秒百万个样本；本项目一个样本是一对I/Q |
| FFT | 把一段时域样本转换为各个频率位置的复数频谱 |
| bin / 频率格 | FFT的一个离散频率位置，当前相邻格相差9765.625Hz |
| PS / PL | Zynq的ARM处理器系统 / 可编程FPGA逻辑 |
| DMA | 硬件搬运数据，本项目将DDR数据送入非活动Bank |
| Bank | 一块完整可回放的IQ缓冲存储，双Bank允许装入与分析交替 |
| BRAM | FPGA专用块存储；当前占用128/140个36K等效Tile |
| LUT / FF / DSP | 组合逻辑查找表 / 触发器 / 专用算术单元 |
| MMCM | FPGA内产生和管理时钟的专用模块 |
| CRC / SHA-256 | 传输完整性校验 / 文件字节身份核验；用途不同 |
| POR | 上电类复位迹象，不自动等同于“USB线坏了”的完整根因 |
| 冷启动 | 本次由用户实际断开并恢复供电后的启动，区别于软件复位 |
| tag / branch / release | 固定提交标记 / 可继续发展的分支 / 附带下载文件的发布页面 |
